# CAM product audit

Reviewed on 2026-09-08, continuing from the branch checkpoint in [the earlier review](2026-09-07-review.md). Every inventory item below has a disposition, implementation decision and verification evidence. The scope is the current client-only 2D CAM contract; commercial feature parity is not an acceptance condition. The branch remains unmerged.

## Acceptance standards

1. Geometry has priority. Use one canvas and clear pane boundaries. Permanent chrome must help the current task; source filenames, encoding and controller wrappers belong in their owning views.
2. Selection is explicit and consistent across the canvas and tree. Show the operation or geometry being edited, support correction, and explain unavailable actions.
3. Inspection does not edit the document. Measurement produces dimensions, identifies its references, snaps within a screen-space tolerance, and distinguishes exact source geometry from free points.
4. Editing has one predictable transaction. Preview changes, validate inputs locally, commit one undoable change, and restore the opening state on cancel. Switching tools must not silently discard edits.
5. Tool panels show the next decision. Keep actions visible, avoid duplicate headings and generic prose, and disclose advanced or inapplicable choices only when needed.
6. CAM intent is visible. Distinguish direction, kept side, starts, leads, travel, threading, stops, inactive geometry and unresolved decisions before export.
7. Export uses a saved revision and an exact machine setup. Validation identifies the operation and repair action. Do not imply hardware validation or invent machine technology.
8. Keyboard, pointer and touch interactions have predictable focus and cancellation. Supported viewport sizes retain essential actions.
9. Tests exercise geometry, persistence, failures and real interactions. Remove dead code and redundant assertions while retaining meaningful regression coverage.

The [CAM reference research](superpowers/2026-09-07-wire-edm-cam-usability-standards-research.md) distinguishes primary vendor documentation, secondary CATIA corroboration and project design inferences. Its recommendations informed this review; they do not establish feature parity or machine certification.

## Supported limits and deliberate deferrals

- This is a source-based 2D CAM workbench. Source-boundary intersection/fit feedback does not model stock removal, fixtures, wire offset clearance, machine heads, controller state or physical machine motion. Continuous-wire travel therefore requires operator review. Taper/4-axis synchronization, skim strategy generation and full machine simulation were not added for commercial parity.
- Posted-program preview supports its documented XY motion/unit modes. G18/G19, G52–G59 frames, decimal G92 controls and intermediate G92 resets are preserved with warnings where accurate physical interpretation is unsupported. Do not treat such previews as a full controller simulator.
- Canvas selection deliberately targets one contour or segment. Overlap cycling and the Geometry lens resolve ambiguity; bulk multi-selection is not implied. Construction points retain coordinates and inference provenance, not a parametric constraint graph. Minimum feature gap measures source edges before compensation.
- Persistent writes require Web Locks. Temporary fallback remains usable without folder-picker support and preserves existing cache data. Locks coordinate workbench tabs, not other applications modifying a folder. Package, revision and trash recovery is journaled; ordinary add/rename/edit has in-session rollback and reports inconsistent interrupted files. This is not an atomic filesystem database.

These are explicit boundaries of the reviewed contract, not unfinished inventory rows.
