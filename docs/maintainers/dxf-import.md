# DXF CPU processing and cancellation

The synchronous DXF domain APIs remain available to non-browser clients. Browser application services inject `DxfProcessor` into the same import and unit-reimport operations. `prepareDxfImportSource` takes only source text, filename, timestamp and import-unit preference. Planning takes parsed entities and reviewed source metadata. Storage adapters, machine catalogs and workbench objects never enter the worker.

Every browser preparation/planning task owns a fresh module worker with a 90-second deadline. Abort, deadline, constructor failure, clone failure, error and successful completion release the worker, handlers and abort listener. A browser without usable workers receives an explicit diagnostic; it never silently falls back to synchronous UI-thread CPU work. Non-browser use retains the pure implementation. Resource limits still reject the complete preparation and planning retains the original JSON snapshot semantics. Route ordering and geometry algorithms are unchanged.

Preparation includes optional session-only candidate previews, so changing a reviewed unit choice does not rerun geometry on the UI thread. These values are frozen after message cloning and are not stored in project/revision schemas. Controller task identity discards obsolete file reads and replies; cancellation/replacement/unmount stops pending CPU work. UI and WebMCP use the same injected application services, with agent input/version and workflow guards retained.

New project and replacement mutations accept a final synchronous guard. It runs under the mutation lock, after transaction preparation and immediately before the first journal write. Cancellation and stale input at this boundary write no journal or project. Once journal writing begins, the transaction completes or reports its actual failure; late cancellation cannot suppress an already committed result. Reimport also checks the complete reviewed project and original source under the lock, after CPU planning, so a changed source or metadata cannot be overwritten with the old review.

Compatibility: UPID, post schema/capabilities, execution events, engine API, output/audits, package installation and storage schemas are unchanged. No installed package, existing saved revision or original source is rewritten. New browser acceptance failures are explicit worker-start/failure and 90-second timeout diagnostics. Affected drawings require a fresh review/retry or simplification; no partial project is imported. Browser tools retain their argument and receipt formats; their hosted guide describes worker/cancellation behavior.

Tests cover actual task serialization parity, typed resource exhaustion, disposal, timeout, obsolete replies, UI task identity, cancelled file reads, queued cancellation before a journal, late cancellation after journal start and changed reimport sources/projects. Chromium tests execute real module workers, independently inspect persisted source/geometry and cancel a bounded 5,000-line planning workload. Timing is measured as investigation evidence, not used as a test assertion.
