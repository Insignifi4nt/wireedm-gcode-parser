# Saved-process simulation and agent integration

This describes the current implementation boundaries on `feat/upid-simulation-workbench`. It is an unreleased architecture and compatibility note, not a release record. The hosted user guide is [Simulation](../site/simulation.md); the detailed browser-tool contract and evidence are in [WebMCP integration](webmcp.md).

## Ownership and data flow

`EditorPage` selects the simulation source from `program.project.content` only when it is a saved UPID document. Its editable draft remains a separate object. The Simulation tab is lazy-loaded, blocked during editor workflows, and kept mounted while switching tabs so local scenario state survives. The panel pauses when inactive and resets playback when its compiled plan changes. A different open project remounts the scenario.

The canvas fills the available workspace. Stock, Machine, Checks and source information share one non-modal focused popover instead of a permanent sidebar. Hidden sections retain unapplied settings and the import lifecycle. Opening a section pauses playback; Escape closes it and returns focus to its trigger. Outside clicks dismiss it. Checks includes future event-linked findings, preparation diagnostics and failed/incomplete machine scans; selecting a timed finding seeks to that event. Detailed source and approximation text stays in the information panel rather than obscuring the scene.

`compileSimulation(document, settings)` calls the shared `compileWireEdmExecutionPlan`; it does not read controller text, run a post, infer missing machining decisions or write a revision. It returns a frozen plan or diagnostics. `sampleSimulation(plan, time)` deterministically returns the wire, active event, released pieces, stock openings and elapsed findings, allowing seek without replaying a physics world.

The browser calls this operation through a fresh module worker with a 60-second deadline. Changing the saved source, applying settings or leaving the project terminates obsolete CPU work and discards its result. Source identity is checked during render as well as after asynchronous completion. Non-browser clients use the same pure domain implementation. Timeline seeking uses binary event lookup; conservative polygon bounds avoid unnecessary obstruction checks. The scene batches static and completed paths into a fixed set of line buffers and updates only the active path tip during playback.

Simulation settings are explicit, separately validated inputs: rectangular constant-thickness stock, wire diameter, viewing speeds, illustrative event holds, retention, support floor and simplified guide dimensions. `releasedPieces` uses complete source-range coverage to release closed boundaries; partial cuts do not complete an uncut bridge. Nested pieces preserve holes and inherit an earlier enclosing fall. Material outside the stock or below the wire when a later boundary completes produces diagnostics. Falling is a vertical analytic gravity calculation stopped by a support plane, not a rigid-body solver.

Material roles are typed as part, waste or unclassified. Explicit reviewed compensation kept-side intent takes precedence over contour classification, with conflicts diagnosed. Fully excluded source operations do not determine material roles. `wasteHandling` defaults to `remove-before-next-operation`: waste disappears from physical snapshots and subsequent obstruction checks at the next operation boundary, or after settling at program end. `keep` retains it for interference studies. Completed openings survive removal and reverse seeking restores the earlier state. Removal never carries an already separated kept island away with a distant waste ancestor. This is a disclosed operator-removal scenario, not an inserted execution event or generated stop.

`plan.finalMaterial` contains explicit kept solids at authored stock height, a ready/partial/unavailable status and diagnostics. It handles kept exterior pieces, islands, and remaining plate stock for hole-only jobs; partial/unsupported cuts are not invented. Scene presentation is separate: waste is hidden by default, stock can be hidden, and final-part inspection hides process context without advancing playback. Returning to Process restores its camera and time. Visibility cannot suppress collision findings; removal settings can change material presence.

The app places Support Z at the lower wire end by default and validates the Stock form between that end and the stock bottom. Domain callers may still supply a deeper or null support for analysis; these explicit values remain unchanged and produce a support diagnostic. The scene hides the support surface for null support rather than pretending there is a collision plane.

`SimulationScene` owns Three.js objects, GPU resources, camera controls, resize observation and scene capture. `WebGPURenderer` attempts WebGPU and supports its WebGL2 fallback. `SimulationViewport` handles startup failure/retry and releases the scene when its plan or component lifetime ends. Renderer state never changes the source document or execution events.

Extrusion explicitly normalizes outer and hole winding. Nested stock openings replace the containing hole instead of creating overlapping caps; reverse seeking rebuilds the required geometry. Real Three.js mesh-volume and raycast tests cover all winding combinations and retained pieces. A bounded topology pass rejects crossing sampled boundaries and stock-edge contact before extrusion, reporting omitted material while preserving exact wire motion. This matters for very close arcs whose non-crossing analytic boundaries can become crossing polygon chords. Material remains nominal: kerf, spark gap and controller compensation are not subtracted.

Stock, paths and STEP meshes use local vertex origins before Float32 GPU upload, with authored placement retained in object transforms. Regression fixtures preserve 0.02 mm model detail near 999,999 mm. Stock outlines use a 25-degree crease threshold so circular tessellation does not become dense vertical decoration; top/bottom rims and sharp corners remain. Stock and released pieces cast shadows onto the support plane without self-shadow banding on sampled cut walls.

The support grid is a mipmapped texture on a single finite double-sided surface, replacing the nearly coplanar GridHelper/plane pair that disappeared at slight top-view tilts. Camera clipping follows visible scene bounds rather than a fixed extreme near/far ratio. A locally generated HDR studio environment supplies metallic reflections with neutral fill and reduced shadow contrast. Arc-wall normals are smoothed only across small tessellation angles; caps and pronounced corners remain split. The scene owns and disposes these textures along with its geometries/materials; no remote environment-image request is made.

Camera fitting projects the process bounds into the requested view, including the full guides, wire paths, support plane and final released-piece height. Machine fitting includes the transformed assembly too. Top-view scale depends on projected extents instead of an oversized bounding sphere. Failure during scene population, playback, model updates or camera actions invalidates capture, disposes the failed scene and exposes retry. Editor keyboard history is inactive on Simulation; explicit header history/save actions reveal Editor before applying a draft action.

## STEP pipeline and obstruction boundaries

`MachineSetupPanel` owns browser file selection, a cancellable import, progress/errors and alignment drafts. It preserves the current model and placement until replacement succeeds. A completed import resets placement; removing the model or unmounting cancels its worker. Alignment uses `validMachinePlacement` before publishing changes.

Each import owns a fresh worker and Open CASCADE WASM heap. The worker validates a complete STEP envelope with declared length units, requests millimeter output from `occt-import-js`, tessellates and validates typed mesh buffers, bounds, hierarchy and limits, then transfers the buffers. Cancellation, timeout, failure and success terminate the worker. Source SHA-256 is retained in the model. There are no file uploads, arbitrary URL reads or durable model writes. The local LGPL notices and source links in `thirdPartyNotices.ts` must remain visible beside import.

The model is limited to 25 MiB of source, 1,000 meshes, 1,000,000 vertices and 500,000 triangles, with a 90-second worker deadline. Geometry coordinates and translated output are checked against the supported bounds. These are application acceptance limits, not a guarantee that every device can render every accepted assembly. Source geometry is not recentered; placement rotates about its origin, then translates.

Two different checks feed the Checks panel:

- `compileObstructions` samples approximate wire/guide envelopes against rough stock, released pieces and openings. It adds boundary crossings and fall/guide transition times, and exposes a sample-budget diagnostic. This does not solve contact dynamics or imported-machine containment.
- `useMachineCollisionScan` places the imported model and builds its triangle index, then runs cancellable event-linked zero-radius wire/sweep queries. Placement, indexing and scanning share a disposable worker with a 60-second deadline. Source changes terminate it and immediately hide obsolete findings. Buffers are cloned into this worker, leaving the renderer's source arrays intact. Straight segments report surface intersections. Arcs use conservative chord-deviation envelopes, whose warnings have approximate times and locations. Scan budgets and deadlines report incomplete coverage; a terminated worker cannot provide partial contacts or counts. This does not establish solid containment, finite wire clearance, imported guide clearance or released-piece contact with the STEP assembly.

Do not collapse these findings into a generic collision-free or physically verified result. The UI preserves their provenance and limitations. Scenario settings, model and placement are session state, excluded from UPID export, saved revisions and workbench backups.

## Agent and capture integration

`edm_describe_edits` exposes the accepted edit catalog and exact per-kind schemas. Draft mutations remain atomic shared domain operations with editor history. `edm_export_saved_upid` pins the exact saved record hash without changing an unrelated draft. `edm_export_controller` reuses shared generation/audit/download guards. Cancellation is checked before writes, and a durable generation outcome retains its truthful receipt and artifact when cancellation or download failure arrives afterward. `AgentActivity` shows bounded status/errors without recording arguments or project contents.

Preview capture comes from the active app-owned SVG or renderer canvas. The helper validates PNG signature, IHDR dimensions, 1600-pixel and 1 MiB bounds; the adapter rechecks the draft version after asynchronous rendering/hashing. The receipt's `source` identifies 2D/3D, and `contentSource` distinguishes editor-draft pixels from saved-project simulation pixels. `dirty` always refers to the editor draft. A capture is an actual image plus a bounded local artifact receipt, not a desktop screenshot or negotiated inline MCP image response.

The receipt does not contain a full serialized simulation scenario, STEP source or per-frame identity. Draft freshness guards prevent applying a capture to a changed editor state; the image hash identifies the returned pixels. Do not describe this as a reproducible simulation record or a complete saved-project/scenario provenance archive.

## Compatibility checklist

| Area | Simulation and WebMCP impact |
| --- | --- |
| UPID | No new serialized simulation fields or UPID version bump. Stock/support/retention/waste-handling/model placement stay separate. The stricter validation and rare identity corrections on this branch have their own [UPID compatibility record](2026-09-21-upid-compatibility.md). |
| Post schemas and capabilities | Unchanged. No new post property, schema field or capability requirement is introduced by simulation or the new agent tools. |
| Execution events and engine API | Unchanged vocabulary and payload contracts. Simulation consumes the existing compiler output. The separately documented UPID identity fixes can change previously colliding derived plans. |
| Audit and controller output | Shared preflight and output audits remain mandatory; file bytes/rules come from the exact installed post. The direct agent export does not add feeds or rewrite output. Simulation times and findings do not authorize posting. |
| Installation | STEP import is visual geometry, not package installation. Complete `.wireedm-package` validation and exact machine/setup/post references are unchanged. |
| Storage | No scenario/model schema, migration or automatic rewrite. Installed packages, saved revision bytes and original inputs remain intact. Controller generation can create a new immutable revision through the existing guarded operation; downloads alone do not. |
| Browser tools | Adds narrow discovery/export/capture operations and artifact/error details. JSON replies remain bounded. The public agent guide defines cancellation, stale-version and durable-result behavior; ordinary UI controls remain usable without WebMCP. |

The unreleased simulation API adds material roles, removal times, removed-piece IDs and final-material solids/status. Its default support changes from an arbitrary deep floor to the lower wire end, and default waste handling changes from retained debris to assumed operator removal between operations. These affect scenario rendering and obstruction findings only; existing post schemas, execution events, audits, package installations and controller bytes are unchanged. Nothing migrates or rewrites saved documents.

Rendered wire radius is exactly half the configured diameter. Guide meshes remain inside their configured radius, use a height derived from that radius and disappear when the radius is zero. Stock dimensions do not inflate these physical envelopes. Camera clipping and fitting include the actual geometry dimensions.

Focused coverage is colocated with the simulation domain, machine import and scan APIs, `MachineSetupPanel`, controller dialog, preview capture, WebMCP adapters and shared app controller. Real browser rendering/import/capture evidence belongs in the working ledger and final review record; jsdom canvas substitutes are not evidence of GPU pixel correctness. No deployment or physical machine verification is implied by this note.
