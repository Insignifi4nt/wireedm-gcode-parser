# Documentation and release maintenance

Public documentation serves users and cloud-browser agents without a checkout. Internal implementation rationale and release operations live here instead.

- Public HTML and Markdown are generated by `scripts/build-documentation.mjs`; executable browser tools are a Vite entry at `package-tools/index.html`.
- Browser and WebMCP adapters call `runPackageAuthoringTool` rather than duplicate validators. It does not access storage, install packages or fetch remote files. Both invoke it in a cancellable worker.
- Run `npm run post:docs:generate` after contract changes and `npm run post:docs:check` in verification. Generated schema files are not hand-edited.
- Run `npm run build` to publish the app and docs together, then `npm run docs:check` to check static links, discovery and schema parity.
- The initial main baseline is 0.0.685 at 45f142c (685 reachable commits). Each reviewed PR advances the patch once; `npm run release:check -- origin/main` checks the version, lockfile and compatibility record. Rebase/renumber waiting PRs after another release merges.
- Each release record keeps an internal compatibility checklist plus concise `publicNotes`. The published release page/ledger use only user-relevant notes. The Pages workflow tags the source version after checks and before deployment; historical records stay immutable.
- `llms.txt`, Markdown alternatives and sitemap follow https://llmstxt.org/ and static content guidance at https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics. Discovery is scoped to the Pages project path. Origin-level robots.txt and .well-known policy need control of the user-site root; do not fabricate them in a subdirectory.
- WebMCP scope and native browser evidence are recorded in [webmcp.md](webmcp.md). Keep the public `/documentation/agents/` contract aligned with actual registered tools.
