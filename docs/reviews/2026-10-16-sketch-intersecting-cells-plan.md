# Deliberate cells from intersecting sketches

2026-10-16. Read-only assessment of the accepted region architecture and the isolated, untracked `cadSketchArrangement.ts` / `.test.ts`. Those files were not changed, integrated or staged. No tests, native probes, builds or package commands were run. Offset source/review was left frozen.

The earlier overnight task history establishes their origin: this agent was assigned an isolated analytic arrangement module and pure tests, then a typed public seam and explicit Coincident-joint checks, and finally told to freeze them while point interactions continued. Later checkpoints deliberately excluded those files. They are an earlier agent draft, not unrelated user changes. This conversation evidence establishes authorship, not Git provenance or present correctness. Adoption belongs to this new reviewed checkpoint; neither file has been changed during this assessment.

## Decision

This is a useful next substantial checkpoint, but not a compiler flag. Deliver explicit selection of exact **graph-owned** bounded cells through the existing area picker and Pad/Pocket reference path. First support finite transverse line/arc/circle intersections, ordinary declared joints, open tails and disconnected nested circles. A lens and a rectangle divider must both work. Tangency, overlap, unresolved near-coincident events, point-touching material and uncertain multiway crossings reject honestly. Legacy/plugin intersection noding, automatic reference repair and broad topology changes remain outside this first slice.

Keep existing Whole sketch and old selectors unchanged. Previously withheld intersecting components must not suddenly add material to an existing default consumer. New intersecting cells require saved explicit references; opening a new Pad on such a sketch should invite **Choose areas**, rather than silently choosing every discovered cell. The approved saved selection union is the unchanged old reference array OR one `{kind:'graph-cells',sources,cells}` object. A selection cannot mix these representations. This permits an additive CAD schema-2 selector variant without a format migration. A later change to automatic Whole sketch semantics would need a separate compatibility decision.

Official documentation supports selectable regions and a distinction between source curves and profile portions. Onshape Extrude accepts faces/sketch regions and documents selection of closed regions. Fusion accepts one or more coplanar sketch profiles for extrusion. Fusion's API separately exposes a profile portion's geometry and its associated sketch entity. These are useful behavior/model references, not evidence for our persistent naming algorithm. [Onshape Extrude](https://cad.onshape.com/help/Content/PartStudio/extrude.htm), [Fusion Extrude](https://help.autodesk.com/view/fusion360/ENU/?contextId=SLD-EXTRUDE-SOLID), [ProfileCurve.geometry](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_ProfileCurve_geometry.htm), [ProfileCurve.sketchEntity](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_ProfileCurve_sketchEntity.htm)

The isolated test source specifies divider halves, a three-cell circle overlap, dimensions/reorder stability, source-split invalidation, nested holes, clockwise arc clipping, open tails, bow-tie lobes and explicit-coincidence roundoff. These are valuable starting examples. This assessment did not rerun them and does not certify all their assumptions.

Specific adoption risks are visible in the code:

- Its `key` is serialized provisional topology and `geometryKey` is serialized numeric paths. Neither is a reviewed save format. Boundary tokens currently repeat the source's complete knot order; large inputs can make references large.
- `knot` groups nearby parameters and `join` accepts world-roundoff-consistent vertices. The current `32 * EPSILON` parameter grouping can merge a distinct nearby crossing with an endpoint or a crossing of a third support. It must not establish identity. Join only an identical analytic event or an explicitly declared point component, then validate its coordinates against the unchanged roundoff gate. Distinct close events and uncertain multiway incidence report a precision issue. No proximity welding or snapped intersection coordinates.
- The earlier `declaredEndpoint` shortcut also skips any candidate within world epsilon of a declared shared endpoint, and `sharedEndpoint` chooses a nearby endpoint. Fixing `knot` alone would leave that upstream identity error. Recognize exact point equality or a demonstrated endpoint analytic event; a second circular intersection merely near the declared joint remains distinct and must reject if unresolved. Pin both a third-support near-end crossing and the circular second-root case before adopting the draft.
- Branch names depend on ordered source pairs and authored line directions. Circle seam handling and event order require tests crossing the arbitrary angular seam. A source replacement/reversal cannot accidentally retain an old selector.
- One issue currently withholds every arrangement cell, even in unrelated components. This conservative behavior is acceptable initially for **new** graph-cell discovery/resolution, but must not suppress old Whole sketch or old selector behavior.
- `holes` are assigned from negative walks of disconnected components. Union, repeated-node boundaries and point-only contact still need independent invariants. Successful single-cell extraction does not prove selected union.

The old draft's concurrent/multiway examples, including a 100-line case, are not a promise for this slice. Before revising those uncommitted expectations, pin a genuine distinct-near-event counterexample RED and document the unsafe merge it exposes. Keep the useful bridge/face-walk invariants. Ordinary declared joints, the divider's pairwise interior crossings and the lens's two pairwise crossings remain required. Exact multiway analytic intersections can initially reject if their equivalence cannot be established without proximity grouping.

## Reference and dependency contract

Keep numerical `from/to` parameters in the current compiled arrangement only. Recompute them after every accepted source/parameter edit. Persist source/event topology, not `t`, coordinates, sampled points, array indexes, an ordinal area number or a native face key.

Keep the existing `CadSketchCellReference` and its array arm verbatim. Add a new object arm to `CadSketchRegionSelection`, with these agreed roles:

```ts
type GraphCellSelection = {
  kind: 'graph-cells';
  sources: readonly SourceWitness[];
  cells: readonly {
    outer: readonly DirectedSpan[];
    holes: readonly (readonly DirectedSpan[])[];
  }[];
};

type DirectedSpan =
  | { kind: 'interval'; entityId: string;
      from: number; to: number; reversed: boolean }
  | { kind: 'full-circle'; entityId: string; reversed: boolean };
```

The numbers are normalized integer positions in that entity's saved event order, never floating-point geometry parameters or indexes into the `sources` array. An interval names neighboring events in the source's forward order; `reversed` chooses the boundary traversal. For circles the next position wraps cyclically. A circle with no actual events uses `full-circle`, with no phase-zero pseudo-event. Canonical sources are sorted by entity ID, outer loops are rotation-normalized, and holes/cells have canonical descriptor order. No source-index rebasing is needed when combining selected cells.

Each source witness appears once across the whole selection. It contains exact entity ID/kind, line start/end point IDs, arc center/start/end IDs and direction, or circle center ID, plus the complete ordered event descriptors for that source. No coordinates, radii, scalar values, constraint IDs or expression text are copied into the witness. Events distinguish a declared endpoint/joint component from a demonstrated analytic intersection. A crossing owns its canonically ordered entity pair, an analytic branch and any exact endpoint membership; line/circular branches follow the witnessed authored line direction, circular-pair branches follow the ordered centers. Tangent/co-circular uncertain branches are not saved as ordinary transverse events. Circle event order is canonically rotated and remains stable across the arbitrary angle-zero seam.

Capture the selected outer/hole supports and their analytic-incidence dependency closure, including crossing operands. This captures operand kind/point ownership without an implicit dependency on whatever entity later happens to use an ID. Complete event orders can conservatively invalidate another change in that incidence component. Unrelated disconnected components are excluded. The witness is linear in captured sources/events, rather than repeating a long support order in every selected span or cell. The implementation owner must freeze exact schema names and endpoint-event representation with the adapter owner before writes.

The complete event-order witness is a conservative initial policy. If another event is inserted on a captured support, crossing order changes, a source is split/replaced, or construction ownership changes, resolve as stale. Do not select a geometrically nearest replacement cell. A divider moving `x=5 → 3` keeps its left cell; deleting/recreating that divider with a fresh ID does not. New holes change the saved hole descriptor and require deliberate re-selection. Adding an unrelated disconnected component need not change a participating source's witness.

Resolve descriptors against one current accepted arrangement and require a unique exact topological match, then independently validate its current analytic subranges/supports/closure. A numeric geometry change alone updates current geometry; a missing or ambiguous topology match rejects. Saved expressions and all graph points/entities/relations remain byte-for-byte source intent. Crossing-derived vertices are transient and receive no saved point ID or Coincident relation.

`cellId` is an ordinal receipt owned by one prepared graph catalog, document version, sketch and identical proposal. It is not saved, hashed topology or a 96-character authored identifier. Graph inspection rows return this receipt and measurements; the existing chunked reference reader gains a mutually exclusive `cellIds` target alongside its unchanged `boundaryProfileId` target. Reading one or more `cellIds` returns one valid merged selection envelope with each source witness packed once. The prepared catalog performs the same packing for human Shift selection. Pin the expected document version, sketch, mode and exact proposal for all pages/chunks; a receipt from another prepared source must not retarget. No standalone cell-edit tool, catalog service or new history owner.

## Catalog ownership and nested cells

One prepared module lazily owns compatibility/default resolution and a discriminated catalog. The old/default catalog remains the default inspection behavior and returns only existing whole-contour cells. Explicit graph-cell mode returns **all** graph bounded cells exactly once, including simple cycles and disconnected nested circles, not just entities currently flagged as intersecting. Never concatenate old whole-cycle rows with graph-cell rows and try to deduplicate afterward.

For example, three nested graph circles give three graph-cell rows, two annuli and the inner disk. Each has only the new graph descriptor. Their old whole-contour counterparts are absent in this mode. Opening an existing old selector uses only the old catalog; deliberately choosing new graph cells replaces that selector representation after Apply. It never appends graph refs to an old array. The resolver dispatches absent selection and old arrays to the old path, new object selections to the graph path, and rejects malformed mixtures before geometry/native acceptance.

The first graph-cell mode requires a graph and **no nonconstruction legacy profiles**, even when such profiles are disconnected from the graph. Construction legacy profiles may remain and are ignored. This deliberately avoids two competing containment/union systems and ambiguous legacy holes inside new graph cells. Existing Whole sketch and old selectors still resolve mixed legacy/graph sketches through their current path. The restriction is on opting into new graph-cell selection, not a rejection or migration of old documents.

Keep the old/default forest lazy so an arrangement error cannot suppress its existing material. Conversely, new graph mode must not require the old nonintersecting forest to succeed first. The picker captures one catalog and its current mode/selection. It cannot offer an old nested-circle annulus and its equivalent new row together. Keep default-material availability separate from explicit graph-area availability: a selectable lens can enable Pad/Pocket area selection without enabling Whole sketch, Revolve, Sweep, DXF or CAM.

## One material resolver, including selected union

For old selectors and absent selection, retain existing resolution exactly. For new graph-cell selections, deepen the existing prepared-cell/material resolution with one reviewed arrangement-backed branch. Keep pure topology/union independent of `cadSchema.ts` and proposal/inspection modules. Importing inspection from `cadSketchGeometry.ts` would create `Schema → Geometry → Inspection → Schema`; the existing inspection/cache layer wraps the pure resolver, not the reverse. Do not publish intersecting temporary paths as ordinary legacy profiles and run the current nonintersecting contour-forest validator over them: adjacent cells deliberately share boundaries.

For each chosen cell, take its directed outer/hole half-edges. Cancel exact opposing occurrences of the **same current transient source subedge** before any native face exists. Retrace the remaining directed boundary graph; classify positive outer loops and negative holes, group connected regions and validate simple closure/containment analytically. Coalesce adjacent same-support ranges only when it preserves the exact source/event ownership; coalescing is optional. Reject unresolved degree, point-touching unions, duplicate interiors and ambiguous loops rather than extruding each selected cell separately and hoping a fuse repairs it.

This generalizes the current entire-contour cancellation. It must handle selecting lens plus one lobe to reconstruct one original disk; selecting all three circle cells yields the two-disk union, without duplicate interior surfaces. A divided rectangle selected on both sides loses the divider from the material boundary. Selecting an annulus cell alone keeps its hole; adding its disk cell cancels that hole. Multiple disjoint selected components remain supported by the existing region list.

Return an explicit derived analytic material-region arm of outer path plus hole paths, with source descriptors retained separately from presentation metadata. Current `CadResolvedSketchContour` requires an authored/compiled `.profile`, depth and parent. Do not fabricate one merely to fit that type. A narrow common geometry adapter can feed the existing native drawing boundary after union. The same selected-material resolver must serve measurement/depth bounds, datum placement, area repair and overlay. A derived cell boundary is not an authored profile, and a transient node is not a sketch point. Preserve existing public names/fields for old references.

Source eligibility and validation must use the selected regions when a selector exists. `cadSchema.ts` currently checks default nonempty regions before the explicit selector; simply adding a new selector would still fail on a lens-only graph. Update that owning preflight, source eligibility and targeted diagnostics together, while leaving legacy/default resolution untouched. Revolve/Loft/Sweep or exports that lack explicit region selection retain their current contracts; do not silently extend all consumers in this checkpoint. Pad and existing explicit-region Pocket can share the new material resolver.

Legacy/profile geometry is not silently promoted or flattened. Initial new-cell extraction nodes graph entities only and applies the no-material-legacy catalog guard above. Mixed legacy/graph intersections and plugin-generated boundary ownership stay unsupported with an explicit diagnostic. Existing contours keep their prior behavior. No persistent graph IDs are synthesized for plugin segments.

## Compatibility and owned editing

The explicit new selection object can remain additive in CAD schema 2, with no change to authoritative graph/storage formats. Old arrays and saves retain exact originals on read; no migration, automatic solve or selector rewrite. Older releases will reject new selection objects, so document that compatibility limit and test browser-cache/folder save and reopen. The existing save envelope and conflict/journal handling remain responsible for writes. If default material interpretation is changed instead, this additive argument no longer holds: use a separately reviewed format/upgrade with exact-original preservation on both adapters.

Source editing continues through the existing guarded operations and solver preparation. Private sketch local Undo/Cancel/Finish owns temporarily invalid consumers. If a selected cell disappears, loses a hole or crosses a topology transition, explicit area repair replaces its reference; Finish validates the whole part in one accepted commit. Preview/area picking pins current document/sketch/version and the prepared cell set, cancels on source/frame replacement, and never commits from a stale pixel hit.

Human and agent paths use the same `regionSelection` on the existing feature update. Existing region proposals and reference reads must derive the same cells from the same candidate source; reads remain source preflight rather than native certification. No helper may replace this with an unconstrained persisted path copy. Agent batches repair the source and affected consumer selectors atomically.

## Red-first gates and work division

Start with the reference/resolution and union domain contract, then integrate the existing UI/native boundaries. Do not stage the old arrangement files merely because their examples look useful.

1. **Exact cells and stable intent.** Radius-5 circles separated by 6 give lens area `50 acos(0.6) - 24 = 22.36476090008061`, plus two lobes `56.17505543966422`. Paths stay circular subranges. Moving separation to 7 retains lens identity while area changes; source reorder/array changes and crossing the circle's angular seam do not retarget. Tangency/disappearance, source split/replacement and crossing-order changes reject old references. Divider `x=5 → 3` preserves the selected left area `50 → 30`. First pin a distinct near-event counterexample that the old `32 * EPSILON` knot merge mishandles; exact same-event identity remains supported, close distinct events reject without healing.
2. **Union, catalogs and holes.** Lens plus a lobe becomes a radius-5 disk; all three become the two-disk union. Both divider cells yield one `100 mm²` rectangle with no divider boundary. A radius-1 circle inside the lens creates an explicit hole; adding its disk restores the lens. Nested disconnected circles appear once per catalog, never as duplicate old/new rows, and mixed selector representations reject. A material legacy profile blocks only opting into new graph mode; construction legacy does not. Check independent areas, boundary lengths, winding, source subranges and cancellation identities. Pin open-tail exclusion, declared-joint roundoff versus an undeclared gap, tangency/overlap and unresolved events. Old Whole sketch/old selector measurements remain unchanged, including an unrelated formerly withheld crossing component.
3. **Actual native material.** Pad the lens by 5: volume `111.82380450040305 mm³`, exact circular walls and no hidden source mutation. Pad both divider halves: volume `500 mm³`, one solid and no internal divider wall. Inspect section/topology evidence as well as volume; a sum of overlapping extrusions can have the right volume yet retain wrong boundaries. Keep native tests bounded to these and one selected-hole case; no tolerance experiments.
4. **Complete human and agent proof.** Draw two graph circles, open Pad, choose the visible lens, preview/Cancel, Apply and save/reopen with exact references. Change a dimension without changing topology and verify the same lens follows; then remove a crossing, require explicit repair, exercise local/global Undo and Cancel. Repeat with the exact inspected reference through WebMCP proposal/feature update. Pin source/version cancellation and late prepared hits. Run production Chromium/Firefox and one native in-app lens-to-Pad proof before claiming delivery.

Suggested owners: one domain owner audits/refines arrangement and owns typed topology references plus union/resolution; a second owns schema/preparation/proposal/agent/native compatibility; root owns existing picker/feature integration, public docs and browser acceptance. Independent review is essential for event identity and selected union. This is likely a 15–25-file checkpoint with several hundred integration lines beyond the existing roughly 400-line extractor, not a small toolbar follow-up. If persistence/union cannot be kept coherent within this scope, the principled alternative is to keep exact Split/Trim-based contour authoring and expose precise unsupported-area diagnostics while completing this foundation. Do not ship a transient-only lens selector that breaks on the first ordinary dimension edit.
