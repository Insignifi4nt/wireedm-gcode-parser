## Custom feature structure and drag handles

Onshape's FeatureScript UI specification describes typed quantities, conditional fields and collapsible parameter groups. Its manipulator callback receives the feature definition and manipulator changes, then returns an updated definition; one handle can affect several parameters. Quantity results can retain expressions. This supports the principle that drag handles and fields edit one shared definition. It does not imply Wire EDM should execute third-party FeatureScript or adopt its API. [Feature UI specification](https://cad.onshape.com/FsDoc/uispec.html).

Across these families, the current shared candidate preview is separate from accepted history and the accepted native cache. It retains the last valid candidate while the next builds or rejects; Apply requires the current ready candidate, and Cancel restores accepted data. Camera navigation stays available while editing. Form-owned source picks accept only preceding, type-appropriate eligible IDs and preserve the editor's other fields and selection. Export/capture and agent edits remain blocked by the shared workflow checks. These rules are the local implementation choice; vendor documentation does not prove this app's correctness or latency.

## Local assessment and product inference

The following recommendations are our interpretation, not vendor behavior claims:

1. Add explicit selected material regions to Pad/Pocket before exposing a selection control. At this audit point the local schemas contain only a source `sketchId`; native Pad/Revolve and through-all Pocket use every resolved material region. Omitted selection must preserve existing whole-sketch behavior. Resolve nesting before selecting regions so a selected gear keeps its bore, and a nested island can be selected independently. Do not filter raw profiles before resolving holes.
2. A region selector should identify the intended feature input, visibly highlight its material and list chosen regions compactly. Missing/deleted IDs must fail explicitly, rather than silently using another contour or reverting to the entire sketch. Hole interiors versus material regions require a documented semantic choice.
3. A drag handle should modify a pending feature definition, use the same bounds/expressions and preview as typed input, and create one undo step on acceptance. Escape, pointer cancellation, owner changes and stale versions must restore the accepted definition. An exact input remains available when dragging is imprecise or disabled by a relation.
4. Keep accepted geometry distinct from pending native preview. Retain the preceding valid result on an invalid preview, show the failing field or missing selection, and block acceptance/export of the invalid candidate. A lightweight drag display must not be advertised as exact geometry until the native result completes.
5. History and object hierarchy answer different questions. Keep actual modeling order/dependencies visible; add meaningful disclosure, selection highlighting and inline diagnostics before adding rollback/reorder controls. Those controls need real shared operations and tests.

Local source references: `src/domain/cad/cadDocument.ts`, `cadSchema.ts`, `cadPocket.ts`, `src/features/cad/kernel/cadKernelModel.ts`, and `src/features/cad/CadFeatureTree.tsx`.

## Limits and follow-up

This research inspected documentation, not authenticated product sessions. It does not establish latency, pointer thresholds, snapping algorithms, linked-expression drag policy, contour identity persistence, or current CATIA release parity. The current app supports nonintersecting closed analytic contours; arbitrary overlapping-curve region arrangements need separate domain work. No new modeling feature kind or contour behavior was implemented by this research.


## Continued solid interaction audit after the overlay checkpoint

Rechecked the live official Onshape Extrude, FeatureScript UI and SketchUp Push/Pull documentation on2026-10-14. Onshape explicitly supports selecting sketch regions/planar faces, typed depth or a manipulator arrow, direction reversal, symmetric extents and provisional acceptance. These are reference interactions, not claims that the local whole-sketch semantics already support region selection. Sources: [Extrude](https://cad.onshape.com/help/Content/PartStudio/extrude.htm), [Feature UI](https://cad.onshape.com/FsDoc/uispec.html), [Push/Pull](https://help.sketchup.com/en/sketchup/pushing-and-pulling-shapes-3d).

Current source has guarded direct source/body picking and a separate exact native candidate coordinator. A candidate currently carries one complete feature plus isNew; applyCadEdits assembles and validates the entire provisional document before native evaluation. Device preferences currently hold navigationMode and showOnPartDimensions, with no solid-manipulator preference. Any depth-handle implementation must preserve named drivers and correlated shared parameter effects, sign/symmetry and principal/datum normals. Silently replacing a relation with a numeric distance would violate the accepted interaction model. Compound relation handling and stale gesture cancellation need an explicit boundary before exposing a handle. The [Pad/Pocket audit](2026-10-14-cad-pad-pocket-interaction-audit.md) records the completed eligibility fixes and remaining region/handle contracts; no new region or depth controls have been added by this audit.
