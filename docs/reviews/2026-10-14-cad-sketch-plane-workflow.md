# Sketch reference-plane workflow — scoped implementation record

Sketch is now the first model command. An ordinary plane selection changes only view state. Sketch creates one empty sketch on the selected principal or active datum plane through the existing validated `add-feature` operation, then enters drawing. Without a selection it requests a plane in the design area. Plane patches and projected labels are selectable; principal tree rows and active datum rows can complete the same request. The separate tree Create sketch convenience cannot bypass a pending request.

The request owns an exact accepted document object and version. A synchronous owner check consumes it before insertion, rejecting repeated picks in the same event batch and callbacks retained after cancellation or replacement. Escape and Cancel release the workflow without inserting geometry. Missing and suppressed datums are ineligible. Starting the request clears the preceding feature selection so an unrelated inspector does not compete with it.

Root's independent source review found a competing-workflow defect: F2 or a context menu could replace the plane request, and parameters or the part name could start editing. A regression reproduced `awaitingSketchPlane: true → false` on F2 while another workflow remained open. The tree now uses its existing selection-only mode, narrowed to active datums with an explicit principal-plane allowance. Profile, rename, menu and direct creation actions are blocked. Parameters and the document-name input remain locked, while tree disclosure/navigation and eligible plane picks remain usable. The regression verifies the original document/version/history throughout and a correct datum sketch afterward.

Principal plane resources use exact domain frames, bounded view-only patches, local axes and distinct colors; they require no native solid build. Their feature owner is `null`, so a real feature whose ID is `XY` cannot be confused with the XY plane. Existing datum references retain real feature IDs. Source geometry, authored infinite datum planes, saved schema and native precision are unchanged. Empty-scene Create/Pad/Open duplicates have been removed; graphics recovery retains Retry 3D view. Existing sketches are opened from the tree and solid operations remain in the contextual dock and context menus.

`cad_set_viewport` adds strict `select-reference-plane` with `plane: XY | XZ | YZ | { kind: datum-plane, featureId } | null`. It changes no geometry and stays blocked during unfinished workflows or sketch/curve editing. Agents create sketches through `cad_edit_document` with an explicit complete feature; view selection is never an implicit edit input. Read state adds `selectedReferencePlane` and `awaitingSketchPlane`. Rendered `referencePlanes` contains at most three principal values; datum ownership remains in `referenceFeatureIds`. An initial implementation duplicated every datum identity and exceeded the 32 KiB tool response budget for 256 maximum-length IDs; a red-first real controller/tool regression now verifies both maximum-length sketch and datum receipts remain bounded without native work.

Capture validates the exact installed reference version, feature IDs, principal-plane membership and selected plane. A red-first regression caught stale principal glyphs being accepted after selection cleared; current checks reject this. Controller capture also rejects a selected-plane change before artifact publication and retains the previously accepted artifact. Camera navigation, current-build ownership and cancellation guards are retained.

Validation: the first nine flow regressions failed against the old generic Sketch form. The integrated affected-flow run passed 260 cases across eight browser files, with another 20 source/reference cases passing across three files. Two subsequent blank-selection cases passed in the 52-case plane/viewport run. After the independent review repair, 107 cases passed across Workbench, plane flow, empty-scene, tree, datum and parameter editing suites. App TypeScript checking and scoped diff checks passed. The viewport harness uses actual Three.js geometry, camera projection, raycasting and OrbitControls with only the unavailable jsdom GPU renderer replaced; root owns final browser visual verification and publication.

This record covers the plane-selection and creation chunk. It does not establish completion of the overall CAD hardening goal or general face-derived sketch planes.
