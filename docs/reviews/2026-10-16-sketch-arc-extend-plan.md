# Exact endpoint-owned arc Extend

2026-10-16, following accepted local `3cefc297`. Read-only design assessment; only this note changed. No tests, native probes, production edits, builds or package operations were run.

## Scope and public seam

Extend one endpoint of a graph circular arc to the nearest finite transverse boundary in its **unused angular gap**. Keep its source ID, center ID, CW/CCW direction, opposite endpoint and construction flag. A minor arc may deliberately become major. Stop before a full turn; no arc→circle conversion, joining curves, free release location or cutter modification.

Onshape supports extending lines/arcs to a boundary and also permits a free release location. Fusion previews Extend to the next intersection and disallows no-hit extension. Its API distinguishes ordinary endpoint modification from joining or completing an arc into a circle. This slice chooses the bounded Fusion-style no-hit policy and keeps its own exact source/attachment rules; it does not copy automatic constraint creation or joining. [Onshape Extend](https://cad.onshape.com/help/Content/Sketch/extend.htm), [Fusion Trim/Extend](https://help.autodesk.com/cloudhelp/ENU/Fusion-Sketch/files/SKT-TRIM-EXTEND.htm), [Fusion Extend API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_SketchCurve_extend.htm)

Reuse the strict existing `CadSketchExtendTargetSchema` object and all fields. Broaden only `kind` from `'line'` to `'line' | 'arc'`; every other field has the same meaning:

```ts
{ kind, entityId, end: 'start' | 'end',
  boundary: {entityId,index,parameter,position,endpointPointId?}, endPointId }
```

For arcs, `boundary.parameter` remains a **dimensionless normalized source parameter**, below zero for start extension and above one for end extension. It is neither radians nor a global circle phase. Keep the existing line receipt byte-shape and parameter behavior. Verify source entity kind equals the requested kind in the constructor before accepting a witness.

Because the field sets are identical, one strict `Type.Object` with a kind-literal union is sufficient; a top-level differing-field union is unnecessary. This also preserves the actual `.properties.entityId/end` derivation in `CadSketchExtendAtSchema`. Specialize named line/arc target types from the common type when needed. Prepared geometry must be coherent: target line with line `added/extended`, or target arc with arc `added/extended`, plus the unchanged boundary and point. [target/query schema](../../src/domain/cad/cadSketchTrimExtend.ts), [region inspection schema](../../src/domain/cad/cadSketchRegionInspection.ts)

Expose `prepareCadSketchExtend({graph,parameters,entityId,end})` for both supported kinds. Preserve `prepareCadSketchLineExtend` as the strict old line entry point for existing callers/tests. `extendCadSketchEntity` and the existing `extend-sketch-entity` edit requery the common preparer; result IDs do not change. `extendAt` still needs only entity/end; `proposal.extend` carries the same exact target. No new tool, persistent relation, storage shape or solver primitive. The additive operation capability is unavailable in older apps; saved output remains an ordinary existing arc.

## Outward angular query

Use the original center/radius to construct a **real transient full circular support**, then call the existing finite analytic classifier against each unchanged cutter. This is not a proxy full-turn open arc. Preserve `leftParameter:null` for circles in path-intel, derive the angular parameter privately, and keep the cutter's finite endpoint/signed-arc parameter. Do not use clamped `pointOnArcAtParameter(arc,t)` or nearest-point `.t` to construct an extension. No intersection-module API change is necessary. [finite intersection implementation](../../src/domain/path-intel/intersections.ts), [segment factories](../../src/domain/path-intel/segments.ts)

Let `L=abs(source.sweepRadians)`, `D=+1` for CCW and `-1` for CW, and `G=2π-L`. For each actual hit, let `E` be the vector from the center to the selected source endpoint and `H` the hit's radial vector. Measure the oriented angle using `atan2(cross(E,H),dot(E,H))`, with outward sense `D` at the end and `-D` at the start. Select its single outward travel `δ` in `[0,2π)` without an epsilon wrap merge. Eligible hits satisfy **`0 < δ < G`**. Their normalized source parameters are:

- End: `t = 1 + δ/L`.
- Start: `t = -δ/L`.

Only the complementary gap is searched; hits in existing source coverage are not farther extension opportunities. The other original endpoint is the full-turn barrier, never an endpoint to join. Zero added travel and reaching that barrier cannot produce a ready extension. A proven old-endpoint/barrier root must not block a valid nearer gap hit merely because the same cutter also meets it. An unrepresentable/roundoff-ambiguous interval boundary rejects instead of being reclassified as no-hit. A demonstrated actual/declared current-endpoint event may be skipped; a nearby distinct event cannot acquire that identity from distance alone. Relative cross/dot orientation avoids introducing an arbitrary global phase seam; underflow or lost sign must not manufacture zero travel.

Sort each source/cutter pair's full-support roots by the derived normalized source parameter before assigning its existing root index. Keep that deterministic convention in receipts; there are at most two analytic roots. Filter to the usable outward gap, then use the existing nearest-event rule: greatest negative `t` for start, smallest `t>1` for end. Source/cutter array order must not choose a different hit.

Reuse the current event validation and declared-contact deduplication. Each candidate must lie on the source circle and finite cutter within unchanged roundoff. Reject eligible tangent events or undeclared tied contacts; do not discard them and extend to the next edge. Conservatively reject co-support overlap rather than introducing overlap-range repair. Reuse only an analytically witnessed cutter endpoint, never a nearby saved point. Check the selected point against coordinate limits, without rejecting a valid nearer hit solely because an unused farther root is out of range. No finite eligible boundary means unavailable Extend.

## Exact candidate and ownership

At end extension, the added arc runs oldEnd→hit in direction D; at start extension, it runs hit→oldStart in direction D. The resulting source arc has signed sweep `D*(L+δ)`. Certify the **new intended** minor/major class, not the old class: crossing π is valid, while rounding a slightly major/minor result onto π is not. Use the accepted signed Cartesian cross/dot branch checks; a genuine opposite-ray half-turn has no strict side. Independently check original center, both endpoint radii, direction, added+old coverage, nondegenerate added chord and retained total chord, and total coverage strictly below `2π`. No projection, sampled geometry or tolerance changes. The current signed middle-arc certificate provides local reusable math; its name can be narrowed/renamed without changing accepted Trim behavior. [existing signed certificate](../../src/domain/cad/cadSketchTrimExtend.ts)

Reuse `replaceEndpoint` for source construction after the certificate, followed by actual compiled-arc revalidation. Its H/V rewrite is already conditional on line sources, so arc extension must not inherit line direction-transfer behavior. Keep the old point, every scalar string and all unrelated records. Append only a genuinely new numeric endpoint. Require the actual witnessed endpoint ID when available; reject complete-namespace collisions and any endpoint aliasing the retained center or opposite endpoint's declared Coincident component. Interior contact stays a one-time numeric snapshot, with no new Coincident/point-on-curve relation.

Preserve the current conservative blockers: every whole-arc relation owner and every relation/expression on the endpoint being detached rejects. Center-only and untouched-endpoint drivers remain exact. This includes generated Equal radius owners after middle Trim; no implicit radius/equality/corner driver transfer is proposed. Another line may still use the detached old numeric point; keep that line and point unchanged. Report real dependency IDs, not fabricated native conflicts. [reference visitors](../../src/domain/cad/cadSketchGraphReferences.ts), [existing ownership guards](../../src/domain/cad/cadSketchTrimExtend.ts)

Shared preparation already flushes earlier solves, constructs the candidate, runs the existing solver and requires complete candidate equality (`sketch-extend-intent`). Reuse that gate unchanged. A native structural radius equation is already present for the same source arc; no new native equation is needed. Actual domain-query/preparation acceptance must still be proved after implementation authorization; rejection/drift is a blocker to report, not permission to tune convergence. ## Independent design review

Reviewed this frozen plan against the accepted Trim/Extend module, strict target and region query schemas, shared preview/keyboard ownership and current graph constraint references. No blocking design correction remains. This reviewer ran no tests, probes, builds or native work and changed no production files.

The proposed transient circle is the actual analytic support, while cutters retain finite line/arc/circle membership. Relative endpoint/hit cross/dot ordering avoids a global phase seam. The explicit unused-gap bounds, actual current-end identity handling and full-turn barrier prevent an old-coverage hit or nearby distinct contact from becoming an extension. Root indexes and normalized source parameters are defined before filtering, so the receipt is deterministic and requery can reject stale intent. Selected endpoint range checks retain the existing nearer-valid-hit policy.

The intended expanded sweep may cross π. Signed added/total coverage, actual radial side and both radii must establish that result; preserving the old minor/major class would incorrectly block useful extension. The plan includes this distinction and the half-turn/near-half-turn rejection learned from circle Trim. New endpoint aliases of the center/opposite endpoint reject explicitly. Original detached points and source drivers remain, and conservative whole-arc/changed-end owners are not silently transferred.

The strict common object preserves line fields and `.properties` consumers. A generic preparer plus strict old line entry point keeps existing line behavior testable without a second operation or solver path. The coherent preparation tuple fits the current analytic renderer and owned start/end menu. Exact constructor requery and complete prepared-candidate equality remain required for human, proposal and agent edits.

The consumed quarter-arc fixture has an observable material change: the old B→A chord becomes an internal divider after extension to C, so deliberate union of both current cells is essential. Root reports a separately authorized candidate/native feasibility GO for those areas; that does not yet prove the new angular query, endpoint selection, whole-part ownership or production interaction. Those remain implementation gates. No arrangement, source-repair, solver-setting or storage expansion is justified by this design.
