# Saved reference dimensions

Design recorded 16 October 2026, after `cffa7fc` Dimension picking and `8135da5` passive measurements. The initial research did not change production code. Implementation, independent review and acceptance evidence follow below; passive selection readouts alone do not satisfy the saved annotation/conversion requirement.

## Primary evidence

| Source | Supported behavior and limit |
| --- | --- |
| [Onshape Sketch Dimension](https://cad.onshape.com/help/Content/Sketch/dimension.htm) | Driving and driven dimensions are distinct; driven dimensions report implied size without changing geometry and cannot be value-edited. Conversion to driving may overconstrain the sketch. The page also describes automatic conversion when adding an over-defining dimension. We should **not** copy that automatic policy or silently change an attempted driver into a measurement. |
| [Fusion dimensions](https://help.autodesk.com/cloudhelp/ENU/Fusion-Sketch/files/SKT-SKETCH-CREATE-DIMENSIONS.htm) | Driven dimensions follow geometry and display calculated values in parentheses, distinct from editable drivers. Its support for using driven values in other expressions is outside this proposal. |
| [Fusion `isDriving` API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_SketchLinearDimension_isDriving.htm) | Changing a dimension to driving can fail when it would overconstrain the sketch. This supports deliberate guarded conversion, not an unconditional checkbox flip. |
| [Official FreeCAD documentation repository](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Sketcher_ToggleDrivingConstraint.md), [official SketchObject source documentation](https://freecad.github.io/SourceDoc/d9/dad/classSketcher_1_1SketchObject.html) | Reference constraints measure without constraining; driving/reference conversion is an explicit operation. The source documents `setDriving` as changing status and solving. The documentation repository is archived/release-annotated, and the live wiki blocks automated access; do not extrapolate exact latest shortcuts or UI. |

These sources establish the conceptual distinction and conversion risk. The saved IDs, source semantics, deletion policy and implementation below are our proposed contracts. No CATIA-specific claim is required; accessible evidence already answers the bounded question. An unofficial FreeCAD documentation mirror was encountered but is not relied upon.

## Recommended smallest complete slice

Save **aligned line/point-pair length and arc/circle radius or diameter reference annotations**, with explicit Make driving and removal. Retain exact local operand identity; recompute from current geometry on every read/annotation layout. Include construction and linked reference geometry. Exclude angle, arc-length/circumference dimensions, tolerances, names usable by formulas, cross-sketch expressions and an annotation-placement editor. Existing automatic label placement is sufficient initially.

Use one new discriminated relation arm in the existing graph, not a second annotation collection and not a driving relation containing a stale `value`:

```ts
{
  id: string;
  kind: 'reference-dimension';
  measurement:
    | { kind: 'line-length'; entityId: string }
    | { kind: 'point-distance'; pointIds: readonly [string, string] }
    | { kind: 'radial-size'; entityId: string; quantity: 'radius' | 'diameter' };
}
```

There is **no** saved measured number, expression, driver flag, native equation, parameter name or fixed-point effect. The relation's existence/operand identity is authored intent; the displayed number is a calculation. Existing `set-sketch-relation` / `remove-sketch-relation` are sufficient shared agent APIs. Relation IDs remain unique in the current graph namespace. Use the existing schema-derived discovery/inspection surface rather than another tool.

Why distinguish line length from point distance: choosing a line means measuring its current retained edge, including after a supported end trim. Choosing two points means measuring those exact source points, even if an old endpoint is later detached from that line. Preserve the point tuple and entity ID verbatim; no nearest-support lookup, endpoint rewriting or geometry hash. Radius/diameter accepts an actual arc or circle entity and follows its current support without changing its direction/major branch. A linked Use edge may be measured without detaching it.

This arm is passive saved intent, not a new solver constraint. The runtime must explicitly skip it, and DOF/conflict analysis must not attribute any equation to it. Native non-driving distance/radius modes are unnecessary; `createCadSketchMeasurementReader` already measures actual exact local geometry independently of material or solving.

## Conversion and source preservation

**Reference → driving** is a user-visible action on the selected annotation. Keep its relation ID and replace its record with an ordinary existing driver:

| Reference measurement | Explicit replacement |
| --- | --- |
| `line-length` | Existing `distance` over the line's **current** start/end point IDs, with the chosen `CadScalar`. The action deliberately captures those operands at conversion time. |
| `point-distance` | Existing `distance` with the exact saved point tuple and chosen scalar. |
| `radial-size` | Existing `radial-size`, same entity and quantity, with the chosen scalar. |

Seed the scalar editor from the **unrounded computed number**, never from `formatCadQuantity`. The person may type a number, named parameter or expression through existing `ScalarField`. Preview and Apply use the unchanged shared preparation/native solver and independent geometry checks. A conflict or redundancy leaves the saved reference and all accepted geometry/version/history unchanged; the attempted scalar stays editable. No automatic deletion of another relation, expression-to-number transfer, circle-radius release or source-link detach.

Respect known ownership before native work: an existing direct driver can be inspected instead of overwritten; source-driven circle radius and linked Use geometry keep their existing driving guards. A passive reference on that geometry remains valid. A fillet/chamfer owner is not a generic dimension that can be released by this conversion. Rejected conversions must identify actual existing operands/owners; never fabricate a native conflict ID.

**Driving → reference** is optional for the first implementation, not required to start measuring already-driven geometry. If included now, limit it to ordinary `distance` and `radial-size`: explicitly release that one driver's value while retaining the same ID/operands as a passive point-distance/radial reference. This is equivalent in ownership effect to deliberately removing that driver and adding a reference. Preserve all other exact strings/relations and keep parameters. Explain that the dimension no longer drives geometry. Undo restores the exact old driver string; returning to driving seeds the current measured number and does not silently resurrect an old expression. Do not invent dormant expression/provenance storage just to imitate a toggle. Corner/axis/angle driver release remains outside the first scope.

## Decisions to settle before implementation

1. **One-way or two-way first slice:** recommend creating reference annotations and Reference → driving first. Include ordinary Driving → reference only if the explicit release wording/ownership above is accepted. No promise to round-trip a discarded formula without Undo.
2. **Passive edit preparation:** recommend no unnecessary native solve after pending source edits have been flushed and the complete candidate parsed. Pin this small branch before code so passive annotations cannot move geometry or load WASM merely to save text. Keep it inside the existing shared preparation/session guards.
3. **Zero separation:** distinct coincident point IDs can legitimately measure zero. Recommend a saved/readable `0 mm` reference with a label and no invented arrow span; use the existing zero-length-safe geometry helper with a deterministic normal. Make driving still obeys existing native acceptance. Do not loosen geometry validity or invent a hidden point separation.
4. **Axis references:** leave signed ΔX/ΔY out of the first persisted arm. They are useful later through the same reader, but aligned length plus radial dimensions already forms a complete S15 reference/conversion slice. Do not silently interpret a point-distance reference as horizontal/vertical by screen placement.
5. **Duplicate passive annotations:** recommend one existing annotation per exact descriptor/quantity through the human form, restoring its original ID/tuple when selected in reverse. The shared schema need not globally forbid two deliberately placed measurements. A simultaneous driving and passive dimension is valid; it does not become native redundancy.

## Meaningful red-first acceptance

- **Persist/follow with no freedom change:** a40×20 driven rectangle has a saved point-distance diagonal reference. Its value is `sqrt(2000)`; width 60 changes it to `sqrt(4000)` without adding a solver equation or changing its descriptor. Save/reopen and Undo retain exact operand IDs and original width expression. Selected passive readout alone must not satisfy this test; the annotation must exist after deselection/reload.
- **Actual source semantics:** a line-length annotation follows a permitted end trim's retained edge; a point-distance annotation on the original endpoints still measures the full original span. Explicit deletion/cascade handles dependencies. Arc CW/major and circle radius/diameter read actual support without altering direction/strings; a reference can coexist with the existing Radius driver and linked Use owner.
- **Deliberate conversion:** create a reference diameter on an independently free numeric bore, choose Make driving, enter an exact diameter alias and Cancel once. Apply the same record ID through normal preparation, edit its alias, and verify native radius/part volume. A conflicting already-fixed target rejects with unchanged source/session; the reference remains saved and the attempted value is recoverable. Undo returns the exact reference record. No approximate solution correction.
- **Complete human/API proof:** use a normal consumed plate editor, place a saved diagonal reference and a bore reference diameter, Finish, reopen, change width and see the diagonal update, then convert the bore annotation to a driving diameter and rebuild Pad5. Human and `set-sketch-relation` agent definitions match; private Cancel, one complete-part Finish/Undo, cache/folder saves and stale/aborted preview guards hold. No seeded numeric-snapshot reference counts as success.

Expected production scale is roughly100–160 domain/schema/visitor lines,30–60 preparation/runtime/inspection lines and100–150 form/annotation integration lines, depending on conversion direction. This estimate is not a quota. Domain math can reuse current measured-value code, and the only native gate is ordinary existing driving conversion/DOF behavior. No numerical sweep or new solver capability investigation is justified.

## Independent design review

Read-only review against `8135da5` and current source, 16 October 2026. The scalar-free relation is a sound small slice. Start with **one-way Reference → driving**, a zero-distance label without arrows, and no axis/angle/formula integration. No production/test changes, test executions or native probes were made.

1. **Use the existing exact preparation certificate.** Generic set/remove relations currently reach ordinary `flush()`/`solve()` in `cadEditPreparation.ts`; `cadSketchSolutionMatchesInput` deliberately allows free numeric coordinates/radii to change. That alone cannot establish annotation-only immobility. Settle decision 2 in favor of the root's chosen strict preparation: flush preceding geometry, reduce passive metadata, solve and reject drift through the existing exact candidate check. Cover passive-only private Finish `update-feature` snapshots too. The current exact check permits later linked-reference dependents to change numeric components; metadata-only work must certify the complete candidate unchanged, e.g. by extending its existing prefix equality through the final graph sketch. No fast path, numeric mask or new certificate. Driving conversion remains an ordinary solve.
2. **Keep dependency and driver policies separate.** `cadSketchGraphReferences.ts` needs explicit nested measurement operands; its current top-level `pointIds`/`pointId` fallback cannot read this descriptor. Preserve those dependencies for deletion/cascade and inspection. `cadSketchSplit.ts` whole-entity blockers and `cadSketchTrimExtend.ts` entity/expanded-endpoint blockers must not mistake passive records for drivers during otherwise supported surviving same-kind edits. Line-length follows the retained entity; point-distance keeps the original retained points. Missing/incompatible operands still reject. Keep conservative circle-to-arc Trim policy unless deliberately included; a blanket passive exemption should not silently expand surgery support. Move's existing fixed/string guards need no new blocker.
3. **Make driving must replace this ID.** Current panel helpers `distanceRelation` and `radialDimension` may return a different existing driver. Reusing them indiscriminately would violate the same-ID contract or edit that driver while leaving the reference behind. Construct the explicit replacement from this descriptor/current line endpoints. Existing direct drivers, linked owners, circle expressions and corners remain guarded; Cancel/rejection retains the passive record and attempted scalar. Passive radial parsing must accept expression-driven circles without applying the ordinary radial-driver ownership prohibition.
4. **Existing shared APIs are sufficient.** The relation schema already feeds set-relation, feature descriptions and supported-relation discovery. Add an explicit no-equation runtime arm, scalar-traversal identity arm and computed-measurement inspection row; worker source matching must preserve its exact record. Extend typed annotation output with its actual passive relation/mode rather than persisting a synthetic driver. Reuse `createCadSketchMeasurementReader` and current label event ownership, including valid zero separation. Material witnesses, parameter formulas and geometry stay untouched.

This is additive **within schema 2**, but older schema-2 readers still reject the unknown arm. Keep originals, descriptors and driver expressions exact; no read-time solve, measured-value cache or migration. One cache/folder table fixture can prove descriptor preservation. Useful additional boundary evidence is passive-only drift rejection (including Finish), unchanged native DOF/equations, retained-edge versus original-point semantics, and same-ID conversion/Cancel/atomic rejection. These are implementation requirements, not claims of existing coverage for the unimplemented arm.

## Root implementation decision

Proceed with saved aligned line length, ordered point distance and arc/circle radius/diameter references, and one-way Make driving. No driving-to-reference toggle, axis/angle references or formula-from-measurement support. Reference values are calculated, never persisted. Zero separation remains a truthful label without arrows.

Use the ordinary guarded preparation pipeline and its existing exact complete-source certificate for passive-only add/update/remove, including owned Finish snapshots; flush prior actual geometry first. Certify through the final graph sketch so unrelated and linked downstream numeric components cannot move while saving a measurement. Do not introduce another certificate or unchecked metadata session path. Conversion remains ordinary solving. Shared set-sketch-relation may deliberately replace a record, but passive-only classification must not mistake a driving-to-passive replacement for metadata-only work. No production implementation is accepted by this decision.


## Implemented source and independent review

The scalar-free schema/resolver, dependency visitors, ordinary native skip, exact metadata preparation, relation inspection and shared authoring schema are implemented. Human selection offers Reference length/distance/size; labels are parenthesized and use existing aligned/radial geometry. Reference size can choose radius/diameter. Make driving retains the exact ID and uses the unrounded value from clean accepted geometry or the exactly matching solved preview. Pending/error previews offer no invented measured value or conversion seed.

Independent actual-source review found and root/owner repaired five boundary/UI issues: a reused saved annotation left an initial provisional driver behind; a free point paired with one linked endpoint was over-locked; displayed reference values and conversion seeds read unsolved draft geometry; no-hit Trim confused retained point/support references with removed operands; and reference-only append bypassed exact geometry certification. Regressions fail first for each repair. Passive-only set/remove, private Finish, explicit relation deletion and append now share the existing complete-prefix certificate through the final graph sketch. Real geometry appends and driving conversions keep ordinary solving. Native same-ID conversion from a linked endpoint to a free point preserves the complete source and owned supports without detach. The reviewer reports no remaining actionable source finding after rereading the fixes; they ran no checks or probes.

The root five-suite domain/layout/form/cache/folder gate initially passed 123 cases; the shared native preparation/runtime/protocol/inspection gate passed 69. The expanded eleven-suite integration gate passed 195 before the final narrow review repairs. The final changed form suite passes 35 and changed native preparation suite 8. Full TypeScript/build, generated docs/schema parity and pinned native source distribution checks pass after the final implementation. Browser/complete-part acceptance remains in progress at this writing; these counts are bounded receipts, not completion of the broader sketch goal.

Compatibility: additive schema 2 records require a reader that knows reference-dimension; older readers reject them. No migration, measured-number cache, native binary/tolerance change, installed post/package change, app version bump or remote action. Radius/diameter and aligned length are included; axis/angle references, driven-value formulas, reverse driver release and annotation placement editing remain outside this slice.
