# Sketch selection sets and usable pair relations

Internal implementation proposal, 2026-10-16. Reviewed source at `9eedc4575f5a40610a95414db061bd4e3be16b1e`, with concurrent consumer-area work excluded. This note changes no production code. No build, test suite or browser was run for this investigation.

## Recommended first vertical slice

Ship selecting two source points with Shift, editing their straight-line distance or horizontal/vertical alignment in the existing relation inspector, and accepting one prepared edit with working undo and conflict rejection. Include actual selection count, a point/edge filter and a precise alternative to clicking obscured points. Preserve all existing singleton inspectors and point movement. Then add directional box selection through the same set operation. A collection of highlights without a relation command is an incomplete checkpoint.

The graph schema, pinned solver, independent residual check and shared `set-sketch-relation` edit already support these point-pair relations. This slice needs selection and operand preparation, not another solver or history path. [Graph model](../../src/domain/cad/cadSketchGraph.ts), [solver compiler](../../src/features/cad/sketch-solver/cadSketchSolverRuntime.ts), [shared edits](../../src/domain/cad/cadOperations.ts), [preparation](../../src/features/cad/cadEditPreparation.ts)

Defer the Coincident button until declared-joint connectivity is reviewed. Its equations already work, but the material compiler currently follows endpoint identity, not coincidence relations. Making two distinct endpoints coincident does not yet join their open chains into an extrudable loop. The isolated arrangement module has declared-coincidence union logic, but integrating arrangement is outside this selection work. The agreed first checkpoint exposes Distance and Horizontal/Vertical. Never merge persisted point IDs or infer connectivity from proximity. [Compiler adjacency](../../src/domain/cad/cadSketchGraphGeometry.ts), [isolated arrangement](../../src/domain/cad/cadSketchArrangement.ts)

## Vendor evidence and our choice

Onshape documents additive/toggle click selection, empty-space clearing, distinct curve/region hover, and directional boxes. Its modifier policy differs from the proposed app policy. Its Select other command offers an explicit candidate list and keyboard cycling for obscured sketch curves. This supports separating the default hit from an accessible overlap chooser. [Onshape selection](https://cad.onshape.com/help/Content/Home/selection.htm), [Select other](https://cad.onshape.com/help/Content/Home/select_other.htm)

SketchUp documents plain single selection, Shift toggling, separate add/subtract modifiers, and left-to-right containment versus right-to-left crossing. Fusion documents the same box directions, Ctrl/Cmd toggling and Shift adding. There is no universal click modifier to copy. Use plain click to replace and Shift to toggle because that is the chosen app contract, and state it in help. Preserve Ctrl/Cmd for existing browser/application shortcuts. [SketchUp selecting geometry](https://help.sketchup.com/en/sketchup/selecting-geometry), [Fusion selection](https://help.autodesk.com/view/fusion360/ENU/?guid=SLD-SELECTION)

Fusion treats sketch points, curves, profiles and constraints as distinct filter categories. Onshape supports selecting operands before applying constraints and highlights related geometry during constraint inspection. Our point/edge filter and exact operand summary should do real work before a command is offered. [Fusion filters](https://help.autodesk.com/cloudhelp/ENU/Fusion-Model/files/SLD-SELECTION-FILTERS.htm), [Onshape constraints](https://cad.onshape.com/help/Content/Sketch/working_with_constraints.htm)

These are documentation findings, not product usability measurements. Sources were read on 2026-10-16; external products were not operated. This proposal narrows the earlier [workflow reference](2026-10-16-sketch-workflow-reference.md), whose code snapshot predates graph solving, corners and owned sketch editing.

## One selection owner and a small interface

Keep `CadSketchGraphSelection` as the target type so existing singleton callers remain easy to adapt. Replace the singleton `graphPick` with one graph selection owner in Workbench:

```ts
type CadSketchGraphSelectionSet = readonly CadSketchGraphSelection[];
// Stored with document/sketch identity. Empty means no graph selection.
// singleGraphTarget = items.length === 1 ? items[0] : null.
```

The set permits points and entities together, with unique typed identities. Existing legacy profile selection remains singleton and mutually exclusive, maintained through the existing central select-graph/select-profile functions. A legacy contour cannot become four implicitly selected graph edges. A material cell, dimension label and inspected relation do not enter this operand set. They retain their owning workflows and may deliberately set graph operands through the same selection operation. There is no saved selection schema or automatic profile promotion.

Derive `singleGraphTarget` and the old public singleton field from this array; do not retain synchronized singleton graph state. Keep local legacy handle focus in Canvas as an owned grip detail, not another graph selection. This scoped replacement avoids rewriting unrelated legacy profile behavior in the first checkpoint.

Put set rules in a focused pure `cadSketchSelection.ts` module. Its useful interface is selection update plus source reconciliation, both returning immutable values. Update takes current selection, incoming typed graph targets and `replace` or `toggle`. Validate all IDs against the current sketch before returning, reject duplicate request operands, and leave the prior selection unchanged on failure. Use one implementation for pointer, keyboard, chooser and viewport requests. The accepted first bound is 64 selected graph targets for UI and agents; if a box would exceed it, explain the limit and keep the previous set. Never silently choose the first 64.

Array order records selection order. The last remaining item is the primary inspection/focus target, so no second `activeId` is required. Re-adding a removed item makes it primary. Box candidates append in stable kind/ID order. Pair relations are symmetric: canonicalize their two point IDs when finding an existing relation or creating one, without making geometry-array order meaningful.

## Click, filter, overlap and box behavior

- Plain click replaces with the highest-ranked eligible target. Empty click clears. Shift-click toggles one target; Shift-click on empty space leaves the set intact. Shift+Enter/Space on a focused graph item performs the same toggle.
- Shift selection never begins point movement or a legacy grip drag. For a prior multi-selection, the first plain point gesture collapses to that point without moving it; the next single-point drag retains current behavior. This avoids implying a group move that does not exist. Arrow movement is available only for one selected point. Multi-selection never moves an implicit primary point.
- Use a real sketch filter with Auto, Points and Edges. Auto ranks graph points before edges and retains legacy profile fallback only when graph geometry has no eligible hit. Points excludes profiles and curves; Edges excludes points and profiles. A legacy profile remains accessible in Auto and through its tree entry. Filters apply before hit ranking, overlap choice and box queries; changing them does not mutate or reinterpret the current selection. Show selected kind/count and explain ineligible command operands.
- Default graph picking consumes the existing prepared all-hit list, including when the event arrived through a graph SVG child. The child still contains the parent click and keeps keyboard focus semantics. Never re-run profile fallback after a graph selection has been handled.
- Provide Select other in the existing sketch context menu at the observed location. List all eligible graph hits with kind, stable short ID and useful endpoint/entity detail; hover/focus temporarily highlights the candidate, Enter/click chooses it, Escape closes unchanged and restores focus. The chooser snapshots source document, version, sketch, spatial frame, filter and toggle intent. A source/frame/lock change dismisses it. Do not require long-press timing or steal right-button panning. A small inspector operand list can offer the same precise selection route for coincident points, including keyboard-only use.
- A primary left drag from empty space in Select begins a box only after the existing four-pixel movement threshold. Empty means no eligible graph target, legacy grip or legacy profile under the current filter. A curve is its analytic stroke, not a filled interior. Right/middle pan, drawing, dimension labels, menus and owned point drags cannot become a box.
- Determine direction in client pixels before SVG Y inversion. Left-to-right contains the entire analytic entity; right-to-left selects an entity with any stroke portion inside or on the box. Points use their exact evaluated location. A box wholly inside a circle selects no circle unless the circle stroke touches it. Center inclusion alone cannot select a circle edge. Points and virtual sharp-corner witnesses follow the point filter; entity selection never implicitly selects endpoints or centers.
- Box preview is transient. On release, apply once using its captured base selection; Shift computes toggles against that base, not repeated per-move toggles. Cancel restores the base and creates no edit/history. Suppress the browser's following click so it cannot clear the released selection.

Extend the existing prepared interaction module with a box query rather than creating a second geometry cache. Full line/circle/signed-arc bounds give exact containment. For crossing, use bounds only to reject; then test an analytic point on the entity inside the box or exact intersections with its four line edges. Reuse `classifyPathSegmentIntersection` with the CAD roundoff policy. Do not use tessellated preview vertices, DXF clustering, grid snapping, planning default tolerances or AABB overlap as the final crossing decision. [Prepared geometry](../../src/features/cad/cadSketchGraphInteraction.ts), [analytic intersections](../../src/domain/path-intel/intersections.ts), [curve bounds](../../src/domain/path-intel/segments.ts), [CAD roundoff policy](../../src/domain/cad/cadAnalyticSegments.ts)

## Lifetimes and pair-command ownership

Selections belong to one document/sketch identity, not one document version. On an accepted same-sketch edit, reconcile membership by kind and stable ID, retain surviving targets and re-evaluate command eligibility. On document/sketch switch, leaving the editor or starting a drawing tool, clear selection. Do not recover a removed target by coordinates, array position or a nearby edge.

Every box, overlap chooser and relation draft additionally owns its exact source document/version and operation token. Cancel it on source change, unmount, lost capture, pointercancel, blur, external lock, tool switch or spatial frame change during a spatial gesture. Compare the existing center/span/viewport rectangle/plane values. Canvas's full rendered revision also changes for selection and preview, so using that revision blindly would cancel an operation because of its own highlight. Do not introduce a second camera model. Do not clear valid unrelated selection merely because a solve completed. Escape first belongs to the active form, chooser or captured gesture; only idle selection Escape clears the set. Audit the current broad `cancelSignal` clearing when wiring this distinction.

Exactly two distinct graph points enable two-point Distance and Horizontal/Vertical. Seed distance from evaluated positions, retain the exact accepted driver string, and use the shared scalar field for edits. Show both IDs and highlight both operands. Reopening an existing unordered pair/kind edits its relation; it does not add another driver silently. Do not remove a different or conflicting relation automatically. Fixed coordinates and expressions stay authoritative; shared preparation reports native conflict/redundancy or strict residual rejection and leaves the accepted source untouched.

Keep singleton line H/V/length, point coordinate/fixed-axis, circle radius and selected-corner tools unchanged. Two selected edges do not masquerade as two points. Mixed selections and larger sets show count/type guidance; they cannot silently constrain a subset. Perpendicular/parallel/equal-length/tangent between entities require typed persisted relation additions and independent checks in a later domain/solver slice. Selection work alone cannot advertise them.

Use existing `set-sketch-relation` through `onEditMany` and shared preparation for pair preview/Apply. Do not directly write solved coordinates or create another commit path. Pending forms block selection consistently with today's workflow guards; Cancel disposes preview and keeps the accepted selection. Graph-set deletion can use the existing single `delete-sketch-elements` command with explicit point/entity lists and its existing cascade policy. Construction changes require an entity-only set. Retain exact originals and one-step undo; defer group motion, mirror and patterns.

## Shared agent controls

Add one viewport command, `select-sketch-geometry-set`, with `selections`, bounded to 64 targets. This command replaces the complete set; an empty array clears it. Pointer and keyboard Shift toggles remain internal interaction operations. Keep the existing singular command as a replace-one/clear adapter. Both validate category membership in the active sketch, expected document version and current workflow/busy state before calling the same selection updater. Agents select source IDs from the existing constraint inspection; they need not calculate screen rectangles or reproduce picking math.

Expose the complete array as immutable `selectedSketchGeometrySet`, including singleton and empty sets. Include its order and filter in visual/capture identity. Keep optional `selectedSketchGeometry` only as a derived singleton compatibility projection. Sixty-four maximum-length typed IDs fit inside the existing tool reply budget; test that bound with other required metadata. Selection paging is unnecessary at this bound. Update the existing viewport/tool schemas, bounded replies, public guide and stale-capture tests together. No new top-level tool, persisted document version or alternate workflow guard is needed. [Existing reply budget](../../src/features/cad/cadViewportToolReplies.ts), [viewport controls](../../src/features/cad/cadWorkbenchViewport.ts)

## Meaningful acceptance tests

| Scenario | Required observation |
| --- | --- |
| Two-point intent | Shift-select two distinct free points, set distance with an exact parameter expression, preview, Apply and undo. Both operands highlight; one accepted history step; source strings and point identities survive. H/V uses both selected points. |
| Conflict/precision | Fixed/driver-owned points reject an incompatible pair distance; redundant existing relation is edited or explained. Native Success with residual failure still rejects. Accepted document, version, undo and storage state remain unchanged. |
| Toggle and focus | Pointer and Shift+Enter/Space yield the same set. Repeated toggle removes one item without clearing others. Text fields and IME retain keyboard ownership. Shift selection makes no solver call or point movement. |
| Singleton compatibility | Normal point drag, per-axis driver limits, line length, circle radius, selected-corner tools and legacy profile/grip selection retain current behavior. Multi-selection cannot move an implicit primary point. |
| Overlap and reorder | Coincident points, crossing lines and a construction/ordinary overlap expose every eligible candidate. Reversing source arrays or SVG paint order does not change default ranking or chooser identities. Hover/focus preview does not alter the accepted set. |
| Analytic boxes | Test a line crossing with endpoints outside; a major arc crossing while its chord misses; a minor complementary arc that misses; tangent contact; a circle surrounding the box with no stroke inside; full containment; reversed drag directions; translated/far-origin geometry. Bounds-only and polyline approximations would fail these cases. |
| Scope/filter | Points-only box can select two endpoints without their line. Edge mode never picks a center. Construction and virtual sharp points are explicit selectable sources. A graph hit cannot fall through to legacy profile/interior or material-area selection. |
| Canceled box | Escape, pointercancel, lost capture, dropped left button, blur, view/source change, second pointer and lock leave the captured base selection intact. Release applies once; the following click cannot clear it. No geometry/history is created. |
| Stable membership | Same-sketch parameter edit preserves valid IDs but cancels old spatial/draft ownership. Delete prunes removed IDs. Document/sketch switch clears all. A split/replacement cannot select a nearby survivor by location. |
| Agent parity | Singular compatibility and set commands use the same reducer. Missing/wrong-category IDs, duplicate operands, wrong sketch, stale version, more than 64 resulting targets and active forms fail atomically. The full maximum-length set fits the reply budget; capture invalidation observes a changed secondary item even when the former primary stays selected. |
| Topology honesty | Coincident equations between distinct open endpoint IDs do not claim a closed material loop under the current compiler. If declared-joint connectivity is added, test exact source preservation, accepted roundoff-only joints and an equally sized undeclared gap remaining open. |
| Owned sketch draft | In a sketch consumed by a solid, pair edits remain local to its owned prefix, local undo works, Finish validates the full part once, Cancel restores it. Consumer-area repair and its selection remain separate. |

Run the pure set/picking cases first, then focused DOM pointer/deferred-completion and real-WASM pair cases. The root should finish with one Chromium and Firefox human workflow plus the equivalent WebMCP selection/edit path. This note reports proposed acceptance, not passing results.
