## Checkpoint 2: readable canvas across zoom

The screenshots show blue endpoint disks covering small teeth, a very large START dot, and tiny grid numbers. The code mixes base-geometry world sizes, zoomed view-box sizes and non-scaling strokes. Make visual sizes consistent in CSS screen pixels using one shared conversion from the current SVG transform/view box and measured canvas dimensions; account for preserveAspectRatio/letterboxing and resizing. Existing measurementDisplayScale is a useful starting point. Do not multiply CSS pixel sizes by devicePixelRatio.

- Ordinary endpoint radius: about 2 CSS px, with a thin outline and little/no opaque fill. Hover: about 3.5 px. Selected: about 4 px with a clear ring. START: about 4–5 px. Pause glyph: about 6 px radius. Keep contour strokes thin and visible underneath. Arc-center and entry/exit decorations should follow the same coherent scale.
- Maintain larger invisible point hit targets around 7–8 px radius. Separate picking from visual radius; preserve existing overlap selection/cycling and line-selection behavior. Large transparent circles must not indiscriminately steal all segment clicks in dense regions.
- At overview zoom, suppress redundant ordinary endpoint markers closer than roughly 6 screen px (use an efficient screen-space bucket/density pass). Always retain selected/hovered points and action markers; geometry stays intact and picking remains possible. Avoid quadratic collision scans on large DXFs. No extra user preference is needed for this basic readability behavior.
- Grid/ruler numbers should stay approximately 11 CSS px at every zoom. Change major tick spacing/density rather than shrinking font: choose familiar 1/2/5 steps to give roughly 70–100 px between labeled ticks, skip overlapping edge labels, and retain correct world-coordinate values. Keep labels legible against geometry and within the canvas bounds.
- Other START/point/action text should remain around 10–11 px, with suitable padding. Keep coincident labels/markers from covering the selected geometry where feasible.

Verify a dense gear with a tiny interior, full-part overview, interior close-up and detailed tooth zoom at fixed viewport sizes, plus a resized narrow canvas. Capture before/after or equivalent comparison screenshots and inspect them, including hover/selected states, stop groups and grid values. Check that screen radii/font sizes remain bounded while geometry zooms. Use this app's allowed ports (3777 dev, 3778 preview, 3107 Playwright), isolated test projects and existing browser tooling.
