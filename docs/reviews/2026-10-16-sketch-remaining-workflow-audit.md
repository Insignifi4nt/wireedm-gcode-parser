# Remaining everyday sketch workflows

Read-only audit, 2026-10-16, against local `6cf152a` and the in-progress line Extend slice. Compared the [original workflow reference](2026-10-16-sketch-workflow-reference.md) and [goal/checklist](2026-10-16-sketch-workspace-checklist.md) with current source. These are concrete static triggers, not new browser or native-solver results. Only this note was written; no tests, builds, package commands or saved records changed.

The original goal remains usable sketch creation, constrained editing, recovery and complete part-building, followed by broader CAD consistency. Selection sets, point editing, direct circle sizing, exact Move/Split, snapping, explicit coincidence and consumed-sketch repair are existing checkpoints. They should not be counted as missing again. Root accepted the bounded line Extend slice after this audit; this note does not claim sketch completeness or CAD parity.

## Five concrete gaps, in order

| Priority | Everyday trigger and current effect | Source and bounded response |
| --- | --- | --- |
| 1 | Draw a fresh rectangle, add a transverse construction cutter, and trim an outer span. Both H/V relations touching its corner are treated as endpoint owners, so the new command is blocked even without a size or position dimension. Extending a fresh rectangle side encounters the same policy. | [`allocateClosedLines`](../../src/domain/cad/cadFreshSketchGraph.ts) creates four point-pair H/V relations; [`assertDependencies`](../../src/domain/cad/cadSketchTrimExtend.ts) blocks any touched relation or whole-entity owner. Make line boundary edits preserve directional intent under the explicit policy below. Keep real dimensional and attachment blockers visible. |
| 2 | Reconnect a Path to a location occupied by two distinct saved points. The resolver correctly reports ambiguity, but drawing accepts only a unique hit and otherwise falls back to grid rounding. The person cannot choose which saved point the new path should actually join. | [`prepareCadSketchGeometrySnaps`](../../src/features/cad/cadSketchGeometrySnaps.ts) returns `ambiguous`; [`resolveDrawingPick`](../../src/features/cad/CadSketchCanvas.tsx) handles only `hit`. Do not choose an arbitrary ID, merge equal coordinates or bypass the opt-in fresh-shape relation policy. |
| 3 | Focus/select a line with the keyboard and press the context-menu key. The menu offers overlap selection, but no Extend end choice. | 4 | Locate a bore 30 mm right and 20 mm above a plate corner. Selecting the two points offers aligned distance and H/V alignment, not independent horizontal and vertical driving distances. The second and third items are selection/drawing recovery work, not requests for another solver investigation. Broader Tangent, midpoint, Offset and reference reuse remain in the original inventory; the measured ordinary tangent limitation is already documented and does not justify another tuning loop before these workflows improve.

## Recommended next slice: preserve line direction during boundary editing

This is the smallest coherent improvement to the tools just delivered. A fresh rectangle should not require deleting its automatic H/V intent merely to trim or extend a line. Directional intent and finite-size/point ownership need different treatment.

| Existing relation/driver | Proposed line Trim/Extend policy |
| --- | --- |
| Parallel or Perpendicular referencing the surviving line ID | Retain the complete relation record unchanged. The constructor must retain the same oriented line support, and normal preparation must still require exact equality of the complete candidate after native solving. Other referenced entities stay unchanged. |
| H/V whose exact unordered point pair is the edited line's original endpoint pair | Explicitly substitute the replaced endpoint operand with the new endpoint, retaining relation ID, kind and operand order. This is an intentional part of the authored boundary edit, not silent source migration. Reject ambiguous ownership when the same endpoint pair also defines another source edge; do not guess which edge the relation means. |
| Other H/V pairs touching the detached old point | Keep their original operands unchanged, along with that old point. For a rectangle's horizontal bottom edge, the adjacent vertical-side relation still belongs to the old corner/side; it must not be rebound to the new cut point. |
| Distance, Equal length, fixed point/axis, affected coordinate strings, or Coincident | Keep the current conservative blocker behavior. These specify finite size, a located point or an explicit attachment; a direction-preserving cut does not authorize releasing or transferring them. Unrelated records remain exact. |
| Line-angle rays, radial/equal-radius and fillet/chamfer ownership | Keep blocked when affected. Angle rays contain explicit endpoint roles; corner relations own more than line direction. Arc radius/support retention needs its own bounded policy. Do not generalize the line H/V rule to arc chords or corner supports. |
| Whole-entity deletion, including Trim with no intersection | Keep the current strict policy. Direction-preserving retention assumes a surviving source line, so deletion needs a separate deliberate rule. |

Do not merely ignore all point relations, drop blockers, clone every touched relation, or leave the old endpoint-pair H/V as the only claimed direction driver of the new line. Those approaches either lose intent or bind the wrong geometry. Preserve exact scalar text, old points, source bytes and unrelated relation records. Keep witness validation, namespace checks, explicit consumer-area repair and cancellation unchanged. Document the narrowly permitted H/V operand transfer in the domain operation and public agent guide.

Meaningful acceptance would cover a fresh rectangle Trim and Extend with H/V retained, one existing Parallel/Perpendicular pair unchanged, an adjacent old-corner H/V pair unchanged, and distance/fixed/coincident/angle/corner blockers still rejecting. Include reversed source endpoints and explicit boundary-endpoint reuse, then one consumed-sketch reconnection/Pad/Undo/save journey. This needs normal pinned native preparation, not numerical sweeps, new solver settings or arrangement integration.
