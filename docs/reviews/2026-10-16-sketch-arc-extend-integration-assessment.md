# Arc Extend integration assessment

2026-10-16, accepted local baseline `3cefc297`. Read-only code assessment; no production/test edits, native probes, builds or package operations. This note does not establish arc Extend's numerical acceptance.

## Reuse and concrete line-only seams

| Existing seam | Current assumption and bounded change needed |

No new receipt fields are required by the integration code. |

The source-kind extension is not a new saved graph format. Existing schema-2 arcs already store center/start/end IDs, direction and construction; they have no independent saved radius scalar. The old app may reject the newly supported operation, but the resulting ordinary arc records need no storage migration. `CadEditSchema`/schema-derived edit discovery already embed the shared Extend schema; `cadSiteTools.ts` imports the shared query schema rather than reading the target's `.properties` itself. Existing descriptions must accurately broaden from line-only when implementation is delivered.

## Ownership and exact preparation

`replaceEndpoint` already updates one endpoint reference for a noncircle source, retains all original point records, appends only a genuine numeric contact, and invokes the strict graph parser/compiler. Its H/V operand transfer is conditional on an actual line; arcs must not inherit that exception. `assertDependencies` can retain its conservative arc policy with no `retainedLine`: whole-arc radial/equality/corner owners and drivers/point relations on the detached endpoint block. Center-only and untouched-end drivers survive exactly; a detached numeric-looking string is still a driver. An actual cutter endpoint is reused by exact witnessed ID; an interior contact remains nonassociative. No new radius relation is needed for one surviving arc.

`prepareCadEdits` already flushes preceding solves, applies `extend-sketch-entity`, solves the complete candidate, checks cancellation, and requires whole-document equality with the constructor result (`sketch-extend-intent`). This includes detached old points, other geometry and scalar strings. Neither the final equality certificate nor the strict structural endpoint-radius checks should change for arc support. The existing native mapping gives each graph arc one structural equal-length equation between its two center-to-endpoint spokes; it has no line-only operation dispatch or new binding requirement.

## Query, private draft and lifetime

`activeSketch` in region inspection already calls `extendCadSketchEntity` for `proposal.extend` and validates a source-only candidate, allowing explicit downstream area repair afterward. `trimAt` is unrelated; Extend keeps the existing mutually exclusive `extendAt` query and exact `proposal.extend`. Current cells remain current on a query. Proposed cell packing and stale saved topology witnesses must use the actual constructor result; replacing an arc endpoint can invalidate a saved contour/cell witness even when its entity ID survives.

`CadSketchEditDraft.validateEdits` already permits the existing edit only for its owned sketch. `useCadSketchEditing.edit/prepare/finish` retain pinned accepted source/version/storage, local workflow ownership, abort propagation, local history, complete-part Finish and one global Undo. No arc-specific draft state or repair path is needed.

Canvas's `currentOverlap` pins the prepared graph, document, version, filter, cancel signal and frame key. Acceptance rechecks the actual SVG frame. The shared `edgeSubmission`, `useCadEditSubmission` and private/controller checks reject cancelled or stale completion; blur/frame/foreign-lock cleanup remains applicable. The renderer and menu can keep these existing owners rather than add another gesture or preview manager. `useCadController.inspectSketchRegions/readSketchRegionReference` already capture inputs before import awaits, guard both ends, and key proposed reference caches by complete document/sketch/target/proposal scope.

## Small acceptance gate before implementation

Authorize a bounded pinned-runtime preflight separately: one known single-arc result with fixed center/untouched-end expressions, a replaced **free** endpoint and an exact numeric contact; then an actual boundary-endpoint reuse variant. Require the complete graph to remain exact, honest native diagnostics and an independently valid original support/signed enlarged sector. The old detached point must remain unchanged. A fully fixed variant is a measured limit, not grounds to omit structural constraints or discard strings. Prior Circle Trim/middle-arc results make reuse plausible but do not prove these exact candidates or a particular redundancy outcome.

After a go decision, the smallest integration proof is the same constructor/query receipt through real exact preparation, preceding solved inputs, one owner/stale-candidate atomic rejection, and `extendAt → proposal.extend → packed reference → explicit consumer repair` with Undo/Redo. Reuse existing cancellation checks, adding only an arc-specific focused-identity/preview case. Native projection, structural mismatch, tangent/overlap, uncertain contact and full-turn collapse stay rejection outcomes; no coordinate repair, tolerance tuning, new edit executor, selection state or adapter service is justified by this assessment.
