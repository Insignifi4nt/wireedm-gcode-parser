# Exact sketch end trim and extend after Split

Investigation only, 2026-10-16, at `4fd7dee` with root's pending circle-sizing work excluded. This note is the only change. No production/tests, solver probes, packages, builds or remote writes.

## Recommended first vertical slice

Implement **end Trim on graph lines/open arcs**, followed by **line Extend to the next finite boundary** through the same checked analytic query/constructor. A click chooses the source span to remove, not an arbitrary cut coordinate. End Trim keeps one surviving source entity ID; with no intersection it previews whole-edge deletion. Initially reject middle-span removal, circles as edited sources, overlaps, uncertain/tangential boundary events and arc extension. Lines, open arcs and circles can be finite cutting boundaries; construction edges can be deliberately used as boundaries without changing their flags. Legacy/plugin profiles are unchanged.

This is useful for removing an overhang or connecting a free line end to existing sketch geometry. It is a bounded part of S16, not a claim that every Trim/Extend mode is complete. Existing [Split](../../src/domain/cad/cadSketchSplit.ts) remains available for deliberate manual partitioning and both pieces remain after it. Trim must independently find the nearest boundary around the owned click and explicitly show the portion removed.

The scope stops before two hidden dependencies: maintaining a new endpoint on a moving cutter needs a point-on-curve relation that this graph does not yet have; maintaining the same infinite support between two disconnected middle-trim survivors is not achieved by Split's `parallel` relation alone. Neither should be smuggled into this slice as a geometry repair or hidden construction bridge.

## Official behavior and app decisions

| Primary documentation | Evidence relevant to this slice |
| --- | --- |
| [Onshape Trim](https://cad.onshape.com/help/Content/Sketch/trim.htm) | Removes to the first intersection/bounding geometry; an unbounded curve is deleted. It also supports dragging across several entities. Single owned clicks are a smaller initial interaction. |
| [Onshape Extend](https://cad.onshape.com/help/Content/Sketch/extend.htm) | Extends a line/arc to a boundary and also permits a free release location. This app can deliberately defer that latter mode. |
| [Fusion Trim/Extend](https://help.autodesk.com/cloudhelp/ENU/Fusion-Sketch/files/SKT-TRIM-EXTEND.htm) | Hover previews the change; clicking uses the next intersection. No-hit Trim deletes, while no-hit Extend cannot proceed. Use that bounded no-hit Extend behavior, with no arbitrary cursor fallback. |
| [Fusion trim API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_SketchCurve_trim.htm) | The picked point chooses the segment to remove. End trims modify the original line/open arc; middle removals replace the original with two entities. Constraint creation is an explicit option. This supports a distinct end-trim identity rule; it does not specify a safe rewrite for our saved relations. |
| [Fusion extend API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_SketchCurve_extend.htm) | Ordinary endpoint extension modifies the original; joining curves and completing an arc to a circle can replace identities. Joining, automatic merging and arc-to-circle conversion are excluded initially. |
| [FreeCAD Trim documentation](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Sketcher_Trimming.md) | Uses nearest intersections, previews endpoints and can transfer applicable constraints/add point-on-object relations. This is stronger persistent behavior than merely saving a numeric intersection. |
| [FreeCAD Extend documentation](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Sketcher_Extend.md) | Supports line/arc shortening or extension; automatic edge/point attachment is explicit and can move unconstrained targets. Our exact edit instead rejects unintended propagation. |

The linked FreeCAD material is the official organization's archived documentation repository; it is behavior evidence, not proof of the current release's complete constraint-transfer implementation. No vendor session or native Trim/Extend trial was run. Identity, relation blocking and exact acceptance below are deliberate app policies, not attributed vendor guarantees.

## Existing implementation to reuse

- [intersections.ts](../../src/domain/path-intel/intersections.ts) analytically classifies finite line-line, line-circular and circular-circular pairs into none, discrete points or overlap, with scale-aware arithmetic checks and tangent-root handling. Its public classifier currently drops its private parameters. Expose a small detached parameterized result from that existing implementation, rather than recomputing circle roots or deriving event identity from rounded coordinates. No DXF planning/healing tolerances belong in this operation.
- [segments.ts](../../src/domain/path-intel/segments.ts) provides exact-source endpoint factories, `arcParameterAtPoint`, signed arc coverage and `pointOnArcAtParameter`. The latter clamps its parameter and cannot extend an arc. [nearestPointOnSegment](../../src/domain/path-editor/pathPointInference.ts) supplies only the transient human click parameter; it also clamps and must not be used as an extension solver.
- [cadSketchSplit.ts](../../src/domain/cad/cadSketchSplit.ts) demonstrates strict named IDs, whole-entity owner diagnostics, nondegenerate cuts and signed arc partition checks. Reuse its precision predicates/math, but do not call Split then Delete inside independently accepted session edits. Split adds parallel children sharing one joint; after deleting a middle interval that topology no longer proves collinearity.
- [graph references](../../src/domain/cad/cadSketchGraphReferences.ts) and [graph deletion](../../src/domain/cad/cadSketchGraphEdits.ts) already distinguish entity owners, point operands and explicit cascade. End trimming must inspect the point being detached as well as whole-entity references; Split's current owner check alone is insufficient.
- [preparation](../../src/features/cad/cadEditPreparation.ts) flushes preceding solves before exact Split/Move and demands complete constructed-candidate equality after solving. Reuse this ownership rule for Trim/Extend. [graph compilation](../../src/domain/cad/cadSketchGraphGeometry.ts) withholds branched/intersecting material; new numeric contact does not grant arrangement cells.

## Analytic query and exact source construction

One proposed focused module, `cadSketchTrimExtend.ts`, should own preparation, witness checking and source construction. Proposed public seams, subject to the accepted narrower scope:

```ts
prepareCadSketchEndTrim({ graph, parameters, entityId, parameter })
// frozen ready description or explicit unsupported/blocked reason;
// span, exact cut point, boundary witness, surviving analytic segment

prepareCadSketchLineExtend({ graph, parameters, entityId, end })
// end: 'start' | 'end'; nearest outward finite boundary and exact candidate

trimCadSketchEntity({ graph, parameters, trim }) // frozen { graph, ...IDs }
extendCadSketchEntity({ graph, parameters, extend })
```

Use strict `trim-sketch-entity` / `extend-sketch-entity` arms on the existing `CadEdit` union, with the sketch ID and named identities. A trim request has `entityId`, numeric source `parameter` in `[0,1]`, and a discriminated result intent: `delete` (no cuts) or `end` with `end:'start'|'end'`, one boundary witness and one cut-point choice. Extend has `entityId`, explicit end, the same witness and cut-point choice. A choice is `{kind:'new',pointId}` or `{kind:'endpoint',pointId}`; do not accept unused split entity/support IDs. A boundary witness names the other entity and its analytic event ordinal within this source pair, in source-parameter order. Recompute and validate that exact event and nearest-span eligibility; reject a changed witness instead of choosing another cutter by array order. Human and agent source-version guards remain mandatory.

**Trim query:** evaluate the accepted graph analytically, find intersections against other finite sketch entities, then order interior events by source parameter. The source endpoints bound the open curve. Locate the one interval containing the click, reject clicks roundoff-indistinguishable from a cut, and remove that interval only. No interior event means whole-edge deletion. An interval between two interior events is explicitly unsupported in the first slice. A tangent, overlap or unresolved multi-edge event that could affect the chosen span is an unavailable result, never discarded so the command accidentally falls through to whole-edge deletion. Multiple boundary endpoints at one declared joint may be one event; undeclared equal-coordinate points are not silently unioned. Sorting/reordering source arrays cannot change the selected event.

**Line Extend:** follow the selected endpoint away from the opposite endpoint, using signed source parameters below zero or above one, and choose the first positive outward distance. The current intersection entry point clips both curves to `[0,1]`, so it cannot be used unchanged. Add one small ray-range path to the existing line/line and line/circular routines, preserving finite membership on the boundary curve and their stable root calculations. Do not create an arbitrary billion-millimetre proxy line or approximate a ray with a polyline. No hit rejects; tied/overlapping/tangent events require explicit resolution or reject. The query must not extend the cutter too.

**Construction:** keep the edited entity ID and source kind/construction/direction, retain the unaffected endpoint ID and every unrelated object/scalar exactly, and replace only the edited end's reference. A new cut point is numeric and allocated once for preview/commit. An explicitly witnessed existing boundary endpoint may be reused only if that actual endpoint is the analytic event and the resulting source support passes unchanged roundoff checks; never choose a nearby point by tolerance lookup. Existing point strings stay untouched. Keep detached original points under the current deletion policy; no implicit point/constraint garbage collection. Report them as retained source points, not moved handles.

Block all whole-entity relation owners initially, including corner/radial/angle/equality/parallel owners, rather than silently rewriting their meaning. Also block a replacement that would detach an exact string coordinate or any relation operand from the changed endpoint. This intentionally includes fresh rectangle H/V and endpoint-distance drivers; the user must explicitly remove/recreate affected relations in the same batch. Relations to the untouched endpoint and unrelated points survive. Structured blocker IDs must resolve to existing human labels; do not fabricate native conflict/redundancy IDs. The narrow policy is conservative and can be relaxed later for proven semantic cases, without a general constraint-transfer engine.

The retained line must lie on its original support at construction. For an arc tail trim, preserve the exact center ID and CW/CCW source, evaluate from the original radial support, and check the retained sweep equals the expected original subrange, including major/minor/half-turn classification. Every retained chord must exceed the current nondegenerate minimum, both endpoint radii must satisfy unchanged structural roundoff, and boundary membership must independently pass the same roundoff policy. Re-evaluating the analytic parameter is construction, not permission to project a failed intersection. No tolerance widening, coordinate welding or JS solve correction.

## Contact semantics and material limits

An interior cut on a boundary becomes an exact **one-time numeric endpoint**. It has neither a saved point-on-object relation nor an implicit declared joint to the boundary's interior. Later boundary edits need not carry that endpoint. The preview/help must say that plainly; use “Intersection cut”, never a “Coincident” badge. An explicit endpoint witness can create a real shared point identity because the edit deliberately owns that attachment; preview must distinguish it. Cutting with construction geometry does not make it material.

Do not split/nod cutters automatically in this slice. A surviving T-junction/interior contact may still be withheld by the current compiler, and a branch must not become a fabricated closed region. If product acceptance requires persistent interior attachment or material cells at those contacts, that is a concrete next dependency, not behavior this constructor can promise. Neither arrangement integration nor a new solver relation is proposed here.

Middle trim is a later bounded extension: it needs explicit survivor identity and support/constraint semantics. In particular, two disjoint line pieces with only `parallel` may slide to different supports. Arc extension also needs separate signed full-support intersection and sub-one-turn coverage checks; `pointOnArcAtParameter` cannot do it, and completing an arc to a circle changes source kind/identity. Circles as edited sources, offset, drag-across trimming, automatic merging and arbitrary cursor extension remain outside this first slice.

## Preview, atomic acceptance and consumer repair

Reuse the owned edge context menu and overlap chooser, with “Trim here” and endpoint-specific Extend previews. Allocate IDs once per pinned menu request. Draw the removed span distinctly from the survivor, mark the exact boundary hit and highlight its source; whole-edge deletion needs an unmistakable full-edge preview. Blocked commands show the actual relation labels. No persistent numeric panel or parallel tool state is necessary initially.

Pin accepted document/sketch/local version, source graph, parameters and SVG frame exactly as Split does. Menu close, Escape, source/version/frame change, tool/workflow change and abort invalidate the request; released callbacks and late async completions cannot commit. One click is one prepared edit/local Undo. Before construction flush earlier parameter/relation intents; after solving accept only the complete constructed candidate, so other points, cutter geometry and driver values cannot drift to satisfy the operation. A failure leaves the entire session/history/storage snapshot unchanged.

Use the existing [private sketch draft](../../src/features/cad/cadSketchEditDraft.ts) for consumed boundaries: local end trim may open the sketch, local Undo can restore it, and Finish still validates the whole part. If no closed area remains, require reconnection before area repair; do not suppress the consumer or bypass full validation. If valid cells remain but explicit [region references](../../src/domain/cad/cadSketchRegionSelection.ts) are stale, reuse explicit area repair and one whole-part Finish commit. Preserving an entity ID is not a certificate that a selected area is still the intended area; do not auto-select the nearest replacement or migrate selectors.

For hosted agents, expose the same edit arms through `cad_edit_document`. Extend the existing region inspection/reference-read proposal with one mutually exclusive trim/extend arm, beside full-sketch and Split proposals; call the same pure constructor with effective numeric parameter values. The agent supplies stable cut IDs, reads exact proposed cells, then submits the geometry edit plus explicit consumer updates in one ordinary guarded atomic batch. No standalone Trim tool or alternate acceptance/history path is needed.

## Meaningful red-first acceptance

1. A numeric line crossing two construction fences: clicking an outer span removes only to its nearest fence; clicking between fences rejects unsupported middle removal. Reversing source endpoints and reordering entities preserves the intended physical side/witness. A no-hit source previews/deletes its edge without removing unrelated points or relations.
2. A CW major arc and CCW minor arc tail trim retain exact center/direction, expected remaining sweep, radius and old source strings. A cut near an endpoint, an unrepresentable far-origin arc or a mistaken complementary-sector hit rejects without mutation. A circle can be a cutter but cannot become an invented open source arc.
3. Line Extend chooses the nearer of two outward finite hits and rejects the opposite direction, no hit, tangent/overlap, tied undeclared endpoints and a boundary arc's complementary support. Exact existing-endpoint attachment shares only the witnessed ID; nearby undeclared points never weld. Interior cuts remain honest numeric-only contact.
4. Fixed-string/end-point distance/H/V and whole-entity owners block with their actual labels/IDs. Explicit prior removal in the same batch is honored. Unrelated exact drivers remain byte-for-byte unchanged. A preceding parameter change is solved before querying; stale witnesses reject instead of retargeting.
5. An injected solver result moving another endpoint/cutter or the cut itself rejects complete-candidate equality. Abort, delayed completion and changed source/frame preserve the accepted snapshot. Local Undo/Redo and Cancel restore exact source; no extra intermediate Split/Delete history entries appear.
6. A consumed closed source may become locally open, then reconnect and Finish through normal full-part validation. A changed explicit area requires an inspected replacement when its reference is stale; equivalent hosted proposal + edit/consumer batch yields the same result. Invalid topology or stale selectors leave the whole accepted part unchanged.

File ownership can stay narrow: one domain query/constructor plus focused tests; additive intersection parameter/ray exposure; existing edit/preparation/draft/proposal adapters; then root-owned context preview/help and one real consumer workflow. First land end Trim, then line Extend using that same contract. Do not advertise middle Trim, arc Extend or persistent cutter attachment until their explicit dependencies are implemented and accepted.
