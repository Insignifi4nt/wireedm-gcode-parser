# Owned editing of consumed sketches

Date: 2026-10-16. Status: the initial owned-edit slice is implemented locally. The proposal below records its design; the implementation notes distinguish delivered behavior and remaining work.

## Implementation notes

`CadSketchEditDraft` wraps the existing bounded session and strict prefix validation. `useCadSketchEditing` connects it to the human workbench, reusing the controller's solver preparation. Human history-tree entry for a consumed sketch claims a distinct main workflow. Local graph edits, shared numeric parameters, previews, analysis and Undo/Redo use the private revision. Finish composes one minimal full-part batch; rejection preserves the edit. Cancel also aborts a pending Finish. Ordinary controller versions and source/storage/workflow guards remain unchanged.

The workbench receives a rolled-back view projection while the controller, public reads, save/export, build and agent operations retain the accepted full part. File/Save, unrelated tree commands and global parameter management are unavailable during ownership. The checkmark finishes; the adjacent Cancel discards the sketch edit. Public `cad_set_viewport` sketch entry remains view-only, allowing agents to use the existing atomic batch operation. The public guide explains this distinction.

Plane/offset fields validate through private preparation on Apply. They do not submit private revisions to the main full-part native preview coordinator. Full-part final preview and deliberate consumer area-reselection UI remain future work. The core accepts explicitly staged direct Pad/Pocket region repairs, but the human inspector does not expose that repair flow yet; a stale explicit region reference still rejects Finish honestly. New drawing also still needs existing-point snapping/reuse to complete a delete-and-reconnect journey without exact API authoring.

## Recommendation

Add one controller-owned sketch edit transaction. Keep the accepted full part unchanged while the user deletes, trims and reconnects graph entities. Give the transaction its own bounded Undo/Redo. Finish runs the ordinary solver and full-part validation, then accepts one main-session history step. Cancel discards the transaction. Do not weaken `parseCadDocument`, persist failed features, suppress consumers in the source, or create another solver.

Use a private, strictly parsed document prefix ending at the edited sketch as the local editing context. The prefix is a real valid document in its own right, rather than an invalid full part typed as `CadDocument`. Wrap a private `CadSession` for its existing immutable history and limits. The public accepted document, saved baseline and build still belong to the main session. This is the smallest reuse of the existing preparation and history contracts. It needs a narrow controller adapter, not another CAD controller.

## Evidence and existing seams

Onshape documents the relevant human behavior directly: Undo/Redo inside a sketch or feature reverses individual actions; after the dialog closes, it reverses the editing session. Its sketch Cancel discards actions taken while the sketch dialog was open. Feature editing normally rolls the view back before later features, with a separate Final preview. These support local history, explicit Finish/Cancel and a rolled-back edit view. They do not require copying every Onshape command or its internal implementation. [Feature tools](https://cad.onshape.com/help/Content/PartStudio/feature_tools.htm), [Sketch basics](https://cad.onshape.com/help/Content/Sketch/sketch_basics.htm), [Feature basics](https://cad.onshape.com/help/Content/PartStudio/feature_basics.htm).

Current official CATIA Exit/Cancel/history semantics were not verified in this investigation. This recommendation makes no claim about them.

## One focused transaction module

Suggested private module: `cadSketchEditSession.ts`. Its responsibilities are begin, local prepare/edit, local preview, Undo/Redo, prepare Finish, Cancel and invalidation. Expose a read snapshot and commands; keep its prefix session and ownership token private. Do not expose save/export/storage methods or a second solver API.

At begin, capture the exact accepted document object, main version, selected sketch ID, connected adapter and an opaque owner token. Parse a detached prefix containing the original document fields, complete parameters/metadata, and features through that sketch. Keep the original suffix pinned separately. Parameter source metadata is historical provenance and does not require a later plugin profile to remain in this prefix. [Schema](../../src/domain/cad/cadSchema.ts), [parameter metadata validation](../../src/domain/cad/cadParameters.ts).

The initial command allow-list should cover graph geometry, relations and construction, existing same-sketch profile commands, and numeric `set-parameter` for linked dimensions. A complete `update-feature` must keep the selected sketch identity and kind. Reject unrelated feature edits, reorder/delete/add feature commands, parameter removal/rename/group edits and package installation inside this transaction. Existing legacy profile validation still applies; this proposal does not make an open legacy closed-path profile valid. Graph trim/reconnect operations still need their own exact domain operations.

Each local command goes through the unchanged preparation pipeline against the current prefix. Accept only the returned parsed prefix into the private session. Capture local version and owner before awaiting; reject an obsolete result without changing local history. Local Undo/Redo restores these snapshots, including exact point/entity/relation IDs and driver strings. Shared parameter changes must pass prefix validation, including any earlier consumers. Do not replay old drag translations against a newer snapshot.

The workbench needs a narrow edit-context projection containing the active sketch, parameters, local revision, local history availability and pending/error state. Route sketch commands and their previews through that context. Keep the accepted full document available separately for the feature tree and controller. Passing the prefix as the global accepted `document` would hide suffix features from unrelated operations and is the wrong integration boundary.

## Finish and Cancel

Finish pins the current local snapshot and stops accepting new local edits. Build a final intent batch against the captured full accepted source: changed prefix feature snapshots, changed/added numeric parameters, and any explicitly approved consumer region-reference replacements. Include earlier prefix graph changes caused by solving shared parameters so the final solve starts from the local branch the user saw. Preserve exact source strings. Reject unexpected differences outside the transaction's allowed ownership.

Pass that batch to `prepareCadEdits(baseAccepted, batch, sameSolver, signal)` inside main `session.editPrepared(baseVersion, ...)`. This matters: parsing the composed full candidate before preparation can reject a graph whose new parameter values still need solving. Conversely, bypassing the final parse would accept a broken solid input. The existing pipeline starts with a valid accepted document, solves the final intent and validates the complete result before acceptance. Keep the existing 256-edit batch limit; never split Finish into several main commits to evade it. [Preparation](../../src/features/cad/cadEditPreparation.ts), [operation reduction and limit](../../src/domain/cad/cadOperations.ts).

On success, release the transaction and return to the accepted full part. One main Undo restores the complete pre-edit part; one Redo restores the result. A no-op Finish makes no history step. On validation or solve failure, retain the local draft and its history, report the actual failure, and leave accepted geometry, main version, saved baseline and redo untouched. Normal kernel rebuild behavior remains the existing controller contract; a successful declarative validation is not proof that a native build has already succeeded.

An explicit `regionSelection` can remain stale after a replacement edge closes the contour. The first increment may reject Finish and keep the draft. To complete that case, let the user deliberately reselect affected consumer areas using proposal inspection, then stage only those consumer selection fields in the same Finish batch. Keep the consumer definitions and choices local until the full batch validates. Do not drop explicit selection, choose a nearby cell or silently reuse a replaced boundary. The existing public agent proposal workflow already follows this rule. [Region selection](../../src/domain/cad/cadSketchRegionSelection.ts), [proposal reads](../../src/domain/cad/cadSketchRegionInspection.ts), [agent guide](../site/agents.md#selecting-extrusion-areas).

Cancel aborts current local work and Finish preparation, invalidates the owner generation, discards local history and releases only its own workflow. It does not call main Undo, replace the document or write storage. Escape first belongs to the current drag, drawing tool, picker or form; provide an explicit whole-sketch Cancel so existing Escape behavior remains predictable.

## Ownership, preview and staging

Add a distinct main workflow scope such as `sketch-edit` so a child form clearing `editor` cannot release the transaction. A scope name is a blocking signal, not authority. The opaque transaction owner must still guard every local command and Finish. Do not temporarily clear the scope to call ordinary edit paths. Retain ordinary agent/save/export/history/storage guards; route only owned human sketch commands to the private context. Existing `preparePreviewEdits` allows only the editor scope and reads the accepted full source, so it needs a dedicated owned-context route, not a broader workflow exception. [Controller](../../src/features/cad/useCadController.ts), [session](../../src/features/cad/cadSession.ts).

Pin adapter, open state, document identity, accepted source/version, owner generation and local revision for asynchronous work. Cancel, unmount, source replacement or storage changes invalidate it. Finish must recheck them immediately before main acceptance, and canceling a pending Finish must prevent its late result from committing. A changed accepted source requires a fresh transaction; do not rebase local geometry silently. Keep transaction ownership stable during preparation because `editPrepared` also checks workflow revision. [Prepared edit checks](../../src/features/cad/cadSession.ts).

The default draft view should show the edited sketch and its preceding supports. Later solids may be hidden, or explicitly shown as the unchanged accepted result. They must not appear to be a freshly evaluated result of an open sketch. Full-part native preview can later reuse the existing preview coordinator when a complete candidate validates. It is not necessary for every local delete/reconnect step. Current unload protection already watches `workflowOpen`, so private unsaved work can block accidental departure without persisting an invalid full part or adding a storage format. [Preview coordinator](../../src/features/cad/cadFeaturePreview.ts), [unload guard](../../src/features/cad/useCadUnloadGuard.ts).

Stage this as an explicit owned edit mode for sketches with active consumers, detected through typed sketch inputs rather than the mere presence of solids. Begin ownership at entry, before any edits. Keep the existing immediate mode for legacy/unconsumed entry paths until migrated deliberately. Do not switch to transaction semantics only after a failed delete; earlier immediate edits would then escape whole-sketch Cancel. Update viewport/tool documentation when an existing public entry begins opening this longer-lived workflow. A no-op owned Finish can preserve the current no-history test, while new tests state the different ownership contract explicitly.

Agents can continue using one atomic `cad_edit_document` batch to replace geometry, parameters and affected consumer selections. The reducer and preparation pipeline validate the final part without accepting intermediate steps. A second public transaction-token tool family is unnecessary for that equivalent operation. Agent edits remain blocked while a human owns a sketch transaction. [Atomic operations](../../src/domain/cad/cadOperations.ts), [preparation](../../src/features/cad/cadEditPreparation.ts), [public workflow contract](../site/agents.md).

## Acceptance cases before UI release

| Case | Required result |
| --- | --- |
| Consumed graph rectangle: delete an edge, then draw/reconnect it | Local open geometry is visible; accepted full source and version stay identical until Finish. Valid Finish creates one main history step. |
| Same edit, local Undo/Redo, then Cancel | Local history restores exact IDs and relations. Cancel preserves main source, version, saved baseline and prior redo. No browser-cache or folder write occurs. |
| Finish while still open, or conflicting relation | Normal full-part/solver failure; local draft stays editable and accepted state remains untouched. Repair and retry succeeds. |
| Replace a boundary used by explicit Pad/Pocket area selection | Stale reference rejects. Only an intentional newly inspected area choice in the same Finish can repair it. |
| Shared parameter drives active sketch, earlier graph and downstream feature | Local prefix and final full part both validate; final solve preserves expression strings and the local source branch. No unrelated source rewrite. |
| Delayed local preview/solve or Finish resolves after Cancel, Undo, document replacement or adapter change | Late result is ignored/rejected; no main or local history mutation and no reopened workflow. |
| Save/export/agent edit/global Undo while owned; local Undo from toolbar/hotkey | External operations remain guarded; local history is used only inside the owned editor. Native text-field Undo remains native. |
| Existing immediate sketch entry, completed contour then Escape, no-op Finish | Existing committed contour survives; Finish still adds no history. This remains covered while the owned path is staged separately. |
