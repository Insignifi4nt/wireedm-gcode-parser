# Persistent reference: independent design review

16 October 2026, accepted Copy checkpoint `10d67ca`. Reviewed the [plan](2026-10-16-sketch-persistent-reference-plan.md) against the current parser, dependency extraction, unsolved reducer, preparation, solver protocol/runtime and private sketch draft. This is a read-only design review: no production changes, tests, native probes, builds or browser actions by this reviewer.

## Decision

Proceed with the bounded line/circle construction-reference design, with the suppression and preparation rules below pinned before implementation. The saved owner is useful dependency metadata, rather than a second authoritative geometry store: its numeric local support is derived, and ordinary complete-document validation independently verifies that snapshot. Same exact principal plane or datum identity with independent normal offsets is sound. Orthogonal projection preserves local X/Y; no world-coordinate subtraction or new transform framework is needed.

The separate [native feasibility record](2026-10-16-sketch-persistent-reference-integration.md) supports this decision. Its five ordinary numeric-fixed states follow the requested line/circle changes with exact protected components; the incompatible circle case produces actual target conflict IDs. These are author-run native results, not production preparation, session, storage or Z-placement acceptance.

## Required boundary rules

1. **Keep the accepted parser strict.** `reduceCadEditIntents` already returns unparsed intent (`cadOperations.ts:106`); `prepareCadEdits` reduces before solving and parses only at acceptance. Refresh each reference from the already solved preceding feature prefix inside that existing pipeline. Do not add a parser bypass, repair-on-read, or last-known snapshot fallback. Ordinary parse/read/build/direct accepted reduction must reject forged or stale values, changed support identity/order, missing/later sources and mismatched bases. Source IDs belong in feature dependencies, not local point traversal or scalar substitution.

2. **Distinguish suppression from broken references.** Current parsing checks structural references and sketch geometry even on suppressed features, but resolves placement only for active sketches (`cadSchema.ts:117–180`); preparation currently solves suppressed graphs too. Preserve that model: every target still needs an existing preceding source, valid witness/base and exact refreshed snapshot. An active target additionally requires an active source. A suppressed target may retain a suppressed-but-existing valid source, allowing deliberate target-then-source suppression; neither suppression permits stale/missing geometry. Creation still selects active sources. Keep current datum availability rules for active features rather than resolving inactive placement through a new permissive cache.

3. **Make the exact-operation phase explicit.** The current exact-command gate compares the complete solved document with the constructor candidate (`cadEditPreparation.ts:45–70`). For the proposed source-following extension, first solve and certify the complete edited prefix through its edited sketch/new feature against that exact candidate. Only then solve later sketches reached through explicit transitive reference dependencies. Only those graphs may change existing numeric coordinates/radii and precisely refreshed owner values; topology, identities/order, relation definitions, strings, profiles, placement, provenance and every unrelated feature remain exact. Reuse the existing comparison discipline; do not mask all suffix numbers or weaken Move/Split/Trim/Extend/Offset/Mirror/Copy globally. Final complete validation must still reject an incompatible downstream part atomically.

4. **Protect numeric ownership at both worker boundaries.** The existing `candidateMatchesInput` deliberately allows all numeric point/radius changes (`cadSketchSolverProtocol.ts:43–52`). Reference-owned numbers must be excluded from that permission, as well as fixed directly through the native parameter API and independently compared after solving. Never encode them as strings. Native Success and missing conflict IDs cannot substitute for exact owner checks and ordinary residual validation.

5. **Detach from the current solved value.** Creation and removing/replacing an existing owner must flush preceding intent before constructing/removing metadata. `[source parameter edit, detach]` keeps the newly evaluated shape; `[detach, delete source]` can commit once. Topology surgery, Move/grips, construction-off and direct coordinate/radius driver controls must recognize ownership and give an explicit detach route. Relation operands against a reference remain usable without giving the target authority over its source. Reversed source direction is a separately authored fixture; changing an existing witnessed endpoint order is not an automatic rebind.

## UI, private scope and acceptance

Reuse the real accepted source canvas and existing entity-pick owner. Intercept eligible tree picks without changing the owned target; render the actual prepared target after choosing; clear that preview before Change source. Keep source/version/frame/foreign-workflow cancellation and existing owned-menu exceptions precise. The source picker must label circles as circles. Derived coordinates/radius should be visibly read-only with contextual Detach, rather than advertised as free and rejected only after editing.

Private target edits admit the new operation only for their owned sketch. Editing a preceding source privately has no later target in its prefix, so Finish must run the same full-part ordered propagation. Existing `inspectAreaRepairs` and repair authorization cover direct consumers of the owned sketch (`cadSketchEditDraft.ts:146–185`), not arbitrary later reference-dependent sketches. Do not imply automatic cross-sketch area repair: retain strict final rejection and identify the affected dependent sketch if its saved selector becomes invalid. This limitation does not block the proposed topology-preserving centered-bore workflow.

The implementation gates are the planned real source Move with exact prefix and protected suffix checks, parameter following, stale/forged snapshot rejection, suppression/detach ordering, private Cancel/Finish and one Undo, human/agent parity, both storage adapters, and actual hole-center/Z-section inspection. The production journey's missing-command RED establishes the entry gap only. No implemented or broader sketch-completion claim is made here.
