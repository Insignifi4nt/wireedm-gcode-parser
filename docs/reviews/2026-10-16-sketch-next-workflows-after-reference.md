## Why the first interaction slice is bounded

`CadWorkbench.tsx` already switches from drawing to Select when opening Dimension, and `CadSketchRelationsPanel.tsx` already owns precise scalar input, preview, Apply/Cancel, expression preservation and existing-driver inspection. `CadSketchGraphLayer.tsx` / `CadSketchCanvas.tsx` already lend a version-owned `entityPick` with eligible IDs, overlap choice, pointer and keyboard activation. Mirror and linked Use demonstrate that this is an operation-local owner, not a new global selection service.

For no eligible preselection, Dimension could enable when an eligible local line/arc/circle exists. Activating it pins the accepted document/sketch/frame and lets the existing canvas pick one actual entity; the successful pick opens the normal Length or Radius/Diameter editor and retires that pick stage. Existing preselected point-pair dimensions and line-angle selection remain unchanged. Escape restores prior selection/tool state without an edit; source/version/lock changes cancel. Read-only linked geometry must not appear editable: it can expose a calculated size, while driving commands retain the existing Detach rule. No new solver, stored selection or command registry is needed.

Static discoverability gaps to verify during the walkthrough:

- `CadSketchMeasurements.tsx` reports whole-sketch/profile area, perimeter and bounds. An individual selected graph line has no corresponding length measurement in that card. The relation form exposes **Add length**, but that creates driving intent. `cadSketchConstraintInspection.ts` entity rows expose points and circle radius, not a general selected line length / point-pair separation result.
- `cadSketchGraphDimensionLayout.ts` and `CadSketchGraphDimensions.tsx` annotate explicit driving relations. There is no saved driven/reference-dimension variant. A read-only selected-size readout would improve ordinary inspection without a new saved model, but would **not** finish S15's persistent reference-dimension acceptance.
- Split/Trim/Extend are real pointer/context commands, and keyboard Extend is delivered. Their absence from the main toolbar alone is not a correctness defect. Establish whether a fresh person can find the existing context command before adding duplicate controls or another floating panel.

Fusion explicitly distinguishes driving dimensions from calculated read-only driven dimensions. That supports clear measurement versus editing labels; it does not require copying its automatic conversion behavior. [Fusion dimensions](https://help.autodesk.com/cloudhelp/ENU/Fusion-Sketch/files/SKT-SKETCH-CREATE-DIMENSIONS.htm) The attempted Onshape dimension page was inaccessible to the web tool in this assessment, so no new claim about its exact invocation order is made.

Minimal meaningful acceptance for priority 1: start from an empty disposable part **without seeded geometry or API selection**, draw rectangle and bore, choose an edge through the actual Dimension command, set width40/height20 and bore offsets/radius, inspect the resulting values without another undo entry, change a visible dimension, Cancel one attempt, Finish and Pad5. Then reopen the consumed sketch, repeat one dimension change, Finish and Undo once. Include pointer, keyboard edge activation and stale source/cancel ownership in a real mounted path. Reuse the existing exact native/agent dimension operations; do not add an API for clicking a button or a copy-only presence test. Expected volume for a40×20 plate with R3 hole is `5*(800−9π)`, but also check bore position and exact source strings. Root's actual walkthrough determines the final fixture and real friction.

## Confirmed consistency gap, not the automatic next project

`cadSketchSplit.ts` still rejects every whole-entity relation through `cadSketchRelationEntityIds`. Consequently, an arc with Radius/Diameter or Equal radius blocks Split, and a line with Parallel/Perpendicular/Collinear blocks despite retaining its support. `cadSketchTrimExtend.ts` now deliberately retains certified radius/direction owners for surviving supports. This is a real command-policy inconsistency in S16; it is not a claim that ordinary unconstrained Split is missing.

If chosen later, the narrow policy can retain those source relation records on the original-ID child while protecting finite Length/Equal length/Midpoint, explicit angle rays, corners and linked-reference owners. Existing shared split point plus line Parallel establishes the two line pieces' common support. Arc children already share their center **and cut point**, so their two structural equal-radius equations establish one support radius. Adding another ordinary Equal radius would duplicate that information; no new arc support-relation field should be introduced without a demonstrated need. Independent signed coverage checks and full exact candidate preparation remain required. A bounded real radius-driven arc Split proof must precede advertising it; this assessment ran none.

### 1. Make a concentric annular part through curve selection

Recommend this next. `CadSketchRelationsPanel.tsx` offers Equal radius for two selected arcs/circles, but no Concentric action. Selecting their center points and applying Coincident already expresses the required persistent relation. Fusion documents Concentric as selecting curved geometry to align its centers, which supports this human entry point. [Official Concentric workflow](https://help.autodesk.com/cloudhelp/ENU/Fusion-Sketch/files/SKT-CONSTRAIN-CONCENTRIC.htm)

Reuse the existing curve-pair panel and guarded `set-sketch-relation` path. Resolve the actual center IDs and author ordinary `coincident`, preserving both point identities, radius driver/source strings and unrelated relations. Concentric aligns centers independently of size; an undriven arc can change radius as the existing constraints solve, so do not promise a size-preserving operation or add an implicit radius driver. Use `resolveCadSketchPointIdentities` in `cadSketchGraphJoints.ts` to recognize an already-shared center/component without a duplicate. A direct existing relation retains its ID and tuple when reopened or restored; transitive coincidence must not offer to remove unrelated links. A fixed or linked center can anchor a free partner. Keep incompatible drivers intact and let normal preparation reject them. This is a contextual human command over the existing agent contract, with no new native equation or saved relation kind.

Red-first complete acceptance: draw two separately centered circles, dimension them Ø20/Ø8, anchor the outer center, select their circumference edges and choose Concentric. Cancel preserves the whole source; Apply locates the free center without equalizing radii. Finish and Pad5 yields an annulus of volume `420π` mm³. Reopen the consumed sketch, change the outer diameter while the bore stays Ø8, then exercise private Finish, Undo and save/reopen. The agent authors the identical center-point relation. Include already-concentric and conflicting-center behavior at shared operations, without a new numerical matrix. This proposed native outcome still needs verification.

### 2. Locate a bore by choosing Dimension, then two points

`CadWorkbench.tsx` already opens `point-dimensions` for a preselected point pair. Its Dimension-first request stores only `eligibleEntityIds`; `CadSketchCanvas.tsx` forces that owner to edge picks. Sequential point picking is therefore unfinished, although the existing Shift-selection route works. Onshape explicitly supports Dimension first, then the first and second point. [Official point-pair dimension workflow](https://cad.onshape.com/help/Content/Sketch/dimension.htm)

Extend that same operation-local owner with typed point/entity picks and a first-point/second-point stage, retaining exact IDs, source/version/frame checks and existing overlap choice. One edge still opens its existing editor. Two distinct points open the existing Aligned/Horizontal/Vertical choices and saved-reference controls; no new solver or storage model. Escape after the first point restores prior selection/tool without history. Prove a human-drawn plate with a bore 30 right and 20 above its corner, no preselection knowledge, plus interrupted picking, stale source, private edit/Undo and the unchanged agent relation tuples.

Editable linear sketch patterns remain the next larger S19 decision. `CadPatternCommand.tsx` handles bodies; it does not supply sketch instance ownership. Saved count/spacing and deleted-instance semantics need a bounded design before implementation, as the [official editable pattern workflow](https://cad.onshape.com/help/Content/Sketch/sketch_linear_pattern.htm) illustrates. Do not call another detached copy command completion. Ordinary Tangent retains its documented radius5→8 native failure; this assessment does not reopen tuning. Split-owner consistency remains recorded above, below these human workflows in priority.
