# Sketch precision policy review

Initial investigation, 2026-10-16, against the frozen Split checkpoint and the existing angle preflight. The investigation read the pinned native source archive in place and made no implementation changes or new experiments. Root subsequently approved the bounded local implementation recorded below, after Split checkpoint `5cdda60`.

## Finding

The current checker uses an arithmetic roundoff allowance as its nonlinear constraint-convergence allowance. Those are different promises. `cadPathClosureTolerance(points)` is `max(1e-12, 8 * Number.EPSILON * max(1, abs(coordinates)))` in millimetres, with an explicit comment that it allows endpoint arithmetic roundoff and never repairs a physical gap. The graph checker reuses it for structural arc radii, coincidence, H/V, distance and fixed-position residuals. Equality, radial dimensions and corner construction also reuse it. [Closure helper](../../src/domain/cad/cadAnalyticSegments.ts), [Graph checker](../../src/domain/cad/cadSketchGraph.ts), [Equality](../../src/domain/cad/cadSketchEqualRelations.ts), [Radial dimensions](../../src/domain/cad/cadSketchRadialRelations.ts), [Corners](../../src/domain/cad/cadSketchCornerGeometry.ts)

Parallel/Perpendicular additionally require normalized direction error at most `1e-12`, and multiply that error by the longer line before applying the world allowance. That independent direction limit prevents a distant origin or tiny second line from licensing a large angular error. The angle plan copies this policy with wrapped error in radians and endpoint deflection `2*sin(q/2)*max(lengths)`. [Line-pair checker](../../src/domain/cad/cadSketchLineRelations.ts), [Angle plan and actual preflight](2026-10-16-sketch-line-angle-plan.md)

The recorded ordinary 120-degree solve has `q = 3.352873534367973e-13` radians, endpoint deflection `3.3528735343686578e-12` mm and distance residual `2.042810365310288e-12` mm. It passes the direction limit but exceeds the current `1e-12` mm floor. That is a few picometres, not evidence of a wrong sector or unusable CAD geometry. The current plan does overconstrain ordinary driver convergence by treating it as analytic encoding roundoff. This conclusion uses the existing report, not a new experiment. [Preflight report](../../tmp/sketch-line-angle-preflight.json)

## What the pinned solver actually promises

The app pins `@salusoft89/planegcs@1.3.0`, publisher commit `9d26baef0b240fe0eef4186d4e5e5e66ec3620b7`, with copied FreeCAD revision recorded separately. Source association is documented; exact reproduction of the original publisher binary is explicitly unverified. [Source manifest](../../vendor/sketch-solver/planegcs-sources.json)

In that pinned `GCS.cpp`, `System::System()` sets `convergence = 1e-10`, `DL_tolf = 1e-10`, `DL_tolg = DL_tolx = 1e-80`, and maximum iterations 100. `solve_DL` returns Success when the infinity norm of its equation residual vector is at most `DL_tolf`; `convergence` is a separate field. The core header itself warns that its fine-precision accessor is not DogLeg precision. [Pinned native implementation](https://github.com/Salusoft89/planegcs/blob/9d26baef0b240fe0eef4186d4e5e5e66ec3620b7/planegcs/GCS.cpp#L2349), [Pinned native header](https://github.com/Salusoft89/planegcs/blob/9d26baef0b240fe0eef4186d4e5e5e66ec3620b7/planegcs/GCS.h)

The published wrapper exposes maximum iterations, a convergence setter and algorithm selection. Its native setter changes only `convergence`; it does not set `DL_tolf` or the other algorithm-specific stopping fields. These fields are public in C++, but absent from the shipped JS binding. The app calls default DogLeg without numerical tuning. Temporary drag constraints select the core's separate constrained solving path, so one DogLeg constant is not a universal runtime accuracy certificate. [Pinned wrapper](https://github.com/Salusoft89/planegcs/blob/9d26baef0b240fe0eef4186d4e5e5e66ec3620b7/sketch/gcs_wrapper.ts#L136), [Pinned binding template](https://github.com/Salusoft89/planegcs/blob/9d26baef0b240fe0eef4186d4e5e5e66ec3620b7/build-bindings/templates/gcs_system.cpp.njk), [Package solving contract](https://github.com/Salusoft89/planegcs/blob/9d26baef0b240fe0eef4186d4e5e5e66ec3620b7/README.md#solving), [App runtime](../../src/features/cad/sketch-solver/cadSketchSolverRuntime.ts)

Native residuals have mixed units. `ConstraintP2PDistance::error()` is `scale * (actualDistance - target)` in native length units. `ConstraintL2LAngle::error()` is a scaled wrapped `atan2` error in radians. Parallel and perpendicular use unnormalized cross/dot products with squared-length units. Therefore native Success at `1e-10` cannot be translated into one guaranteed world-mm or angular error for every relation. Independent physical checks remain necessary, including the recorded all-fixed case that native Success failed to diagnose. [Pinned equations](https://github.com/Salusoft89/planegcs/blob/9d26baef0b240fe0eef4186d4e5e5e66ec3620b7/planegcs/Constraints.cpp), [Angle preflight](2026-10-16-sketch-line-angle-plan.md#actual-pinned-wasm-preflight)

Existing research already tried the public setter, LM and coordinate/unit conditioning. Setter changes did not fix the ordinary arc failures; conditioning introduced accepted-to-rejected regressions. Repeating those trials or rebuilding bindings is not the next step. [Prior findings](2026-10-16-sketch-solver-options.md#production-adapter-foundation-and-remaining-arc-limit)

## Bounded proposal

Retain `cadPathClosureTolerance` for declared-joint identity, complete coincidence classes, structural endpoint-arc consistency, analytic saved-path closure and exact exports. Preserve exact string drivers, immutable source checks, branch checks and the complete-candidate certificates for Move/Split. None of these should inherit a solver-convergence floor. [Joint guard](../../src/domain/cad/cadSketchGraphJoints.ts), [Compiler and encoding](../../src/domain/cad/cadSketchGraphGeometry.ts), [Exact preparation](../../src/features/cad/cadEditPreparation.ts)

Introduce one separately named, fixed app driver-residual budget. A defensible initial candidate is `max(cadPathClosureTolerance(operands), 1e-10 mm)`, anchored to the pinned length-equation stopping threshold rather than a number chosen to pass 120 degrees. Keep the existing `1e-12` normalized direction/radian cap and the longer-line endpoint-deflection check. Independently measured distance and angle errors must pass both relevant checks. This would accept the recorded 120-degree result without changing a coordinate or driver. It would still reject the recorded wrong-sector fixed pair by many orders of magnitude. It is an application acceptance proposal, not a claim that the native threshold guarantees those world errors.

The same named driver budget should eventually cover scalar size, distance, equality and position equations through their existing physical residual calculations. Structural/support/tangency and topology checks need explicit classification before any change, particularly hybrid corner relations. Do not replace every call to the closure helper, or accept a worker result under one policy only to reject it in document parsing under another. Parsing, runtime verification and worker reply verification must share the same reviewed predicate. No per-feature override, user accuracy slider, repair/projection pass, fallback solver or extra settings framework is needed. [Shared graph validation](../../src/domain/cad/cadSketchGraph.ts), [Worker reply boundary](../../src/features/cad/sketch-solver/cadSketchSolverProtocol.ts)

The proposed floor is 1000 times smaller than the app's `1e-7` mm native placement tolerance and minimum supported line length, but those values do not prove a universal model-accuracy guarantee. At large origins, floating-point uncertainty can already exceed the new floor; unrelated circle-center placement must still not inflate scalar-radius tolerances. These facts support keeping distinct contracts, not a global tolerance increase. [Native placement policy](../../src/domain/cad/cadLoftPlacement.ts), [Graph bounds](../../src/domain/cad/cadSketchGraph.ts), [Scalar-radius ownership](../../src/domain/cad/cadSketchRadialRelations.ts)

## Acceptance and risk before implementation

Approve the named physical driver contract first, then implement a small shared predicate and affected call sites. The bounded proof should reuse the existing ordinary 120-degree case, wrong-sector/all-fixed rejection and source-expression checks; add only meaningful boundary cases around the declared budget and one translated/disparate-length case. Existing strict joint, arc-structure and exact Move/Split regressions must remain strict. Ordinary arc failures may remain because their structural representation has a different contract; this proposal does not promise to solve them.

More residual-bearing saved graphs could become valid under a changed driver policy, while older readers still reject them. Record that compatibility consequence and preserve exact saved originals under existing storage rules. Never silently solve, normalize, heal or relabel native diagnostics on load.

## Approved local implementation

The bounded implementation adds [one driver-budget helper](../../src/domain/cad/cadSketchPrecision.ts), `cadSketchDriverTolerance(operands) = max(1e-10 mm, cadPathClosureTolerance(operands))`. The graph's H/V, distance and fixed-point/axis predicates, equal sizes, radial dimensions and line-pair physical deflections now use it. The existing normalized direction cap remains `1e-12`. Circle-radius operands still exclude unrelated center coordinates, and translated point operands retain their existing arithmetic uncertainty allowance.

Coincidence relations, complete coincidence classes, endpoint-arc structural radius equality, source bounds, nondegeneracy, material compilation, analytic path/export encoding and complete exact Move/Split candidate checks are unchanged. Runtime verification, full document parsing and worker reply verification still reach the same shared graph checker. No alternate worker-only tolerance or solve-on-load path was added.

All hybrid corner checks remain unchanged in [cadSketchCornerGeometry.ts](../../src/domain/cad/cadSketchCornerGeometry.ts):

| Corner check | Classification retained in this slice |
| --- | --- |
| Incident entity/trim/reference ownership | Exact topology, no retargeting. |
| Trim point on original support and retained finite interval | Structural construction with arithmetic roundoff and existing nondegeneracy guards. |
| Fillet radius-to-driver and chamfer setbacks-to-drivers | Scalar drivers inside a coupled construction; deliberately retain their stricter existing predicate pending a separate reviewed change. |
| Fillet tangency, intended sign and minor branch | Structural support/branch conditions, unchanged. |

This avoids partially relaxing a corner while its coupled support checks retain another contract. Some ordinary native corner or arc attempts can therefore still reject. No general native-acceptance improvement is claimed for those cases.

Meaningful new tests first reproduced the rejected physical boundary and the recorded 120-degree solve's `2.042810365310288e-12` mm distance residual. A second red-first check reproduced equal-size and line-deflection rejection under the old predicate. The final focused run passes 64 cases across the directly affected domain checks, existing structural/corner/Split tests, pinned native-runtime regressions and the new document/worker boundary tests. It covers exact/in excess physical limits, longer-line and dimensionless rejection, distant scalar radii, translated operands, strict coincidence/whole-class/arc preservation and exact source-driver retention. Evidence: `tmp/sketch-driver-precision-red.log`, `tmp/sketch-driver-precision-size-red.log`, `tmp/sketch-driver-precision-focused.log`. One initial new corner fixture used the wrong treatment field and was corrected to the existing `setbacks` contract; it did not require a production change.

Compatibility changes only numerical driver acceptance. Some schema-2 graphs previously rejected for tiny driver residuals now load and save unchanged; older app versions can reject them. No schema, source record, saved driver, installed package or native binary is migrated or rewritten. This local implementation does not change exact exports, introduce coordinate repair, tune native settings or alter failure diagnostics. Production browser/build acceptance and the release compatibility record remain root-owned.

Root integrated acceptance: final TypeScript/production build and all 23 sketch/region journeys pass in Chromium and Firefox against the same build. Exact parameter-linked angle editing, native solid volume, Cancel/Undo and save/reopen pass without coordinate correction or source rounding. The line-angle review and workspace checklist record final evidence and the older-reader compatibility limit. No release or remote action occurred.
